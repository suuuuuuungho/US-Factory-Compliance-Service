## Codex 메모

### 1. `published_release_id` (ecfr_release.py, fr_release.py)
- `register_release` 안의 "manifest_hash 계산 + 조회" 코드를 그대로 쓰되, `.eq("status", "published")` 조건을 더한다. 해시 계산은 작은 함수(`_manifest_hash(root, as_of)` 등)로 빼서 둘이 같이 쓰면 된다.
- 찾으면 `str(release_id)`, 없으면 `None`.
- 테스트의 가짜 client는 `.select().eq().eq()...execute().data`만 지원한다. `.limit()`, `.maybe_single()` 쓰지 말 것.
- `staging`/`failed` release는 None → 이어서 `register_release`가 기존 id를 돌려주고 load가 다시 돈다 (기존 동작 유지).

### 2. `run_ecfr_ingest` / `run_fr_ingest`
```python
def run_ecfr_ingest(root, as_of, *, client,
                    published_release_id=published_release_id,
                    register_release=register_release, load_release=load_release, publish_release=publish_release) -> dict:
    existing = published_release_id(root, as_of, client=client)
    if existing:
        return {"release_id": existing, "status": "no_change"}
    ... 기존 순서 그대로 ...
    return {"release_id": release_id, "status": "new"}
```
- 키워드 인자 이름은 정확히 `published_release_id` (테스트가 `__kwdefaults__`로 모듈 출처를 본다).
- `format_result(result)` → `f"status={result['status']} release_id={result['release_id']}"`.
- `__main__`: `print(format_result(...))`. FR의 `CheckFailed` 처리는 그대로.
- **왜 no_change 때 load를 건너뛰나**: `fr_load`는 `COPY`라 같은 release에 두 번 넣으면 PK 충돌. eCFR은 upsert지만 71,700행을 매일 다시 쓰는 건 낭비.

### 3. `.github/workflows/db-refresh.yml`
```yaml
name: DB refresh
on:
  schedule: [{cron: "17 3 * * *"}]
  workflow_dispatch:
permissions: {contents: read}
concurrency: {group: db-refresh, cancel-in-progress: false}
env:  # 세 job 공통
  SUPABASE_URL: ${{ secrets.SUPABASE_URL }}
  SUPABASE_SECRET_KEY: ${{ secrets.SUPABASE_SECRET_KEY }}
  SUPABASE_DB_URL: ${{ secrets.SUPABASE_DB_URL }}
jobs:
  ecfr:    # outputs.status
  fr:      # outputs.status
  notify:  # needs: [ecfr, fr], if: always()
```
- job `ecfr`, `fr` 공통: `actions/checkout@v6`, `actions/setup-python@v6`(3.12), `pip install -q -r requirements.txt` (ci.yml `contracts` job과 같은 모양). `timeout-minutes: 60`.
- 실행 명령 (레포 루트에서, 폴더에 공백·대괄호 있으니 따옴표):
  - eCFR: `python "[2] db/pipeline/1_eCFR/ecfr_collect.py"` → `ecfr_parse.py` → `ecfr_ingest.py`
  - FR: `python "[2] db/pipeline/2_Federal Register/fr_collect.py"` → `fr_parse.py` → `fr_ingest.py` (`--end`/`--as-of` 기본값 = 오늘, 그대로 두면 된다)
- ingest 출력에서 status 뽑기: `python ... | tee out.txt` 후 `echo "status=$(grep -o 'status=[a-z_]*' out.txt | cut -d= -f2)" >> "$GITHUB_OUTPUT"`. step에 `id: ingest`, job에 `outputs: {status: ${{ steps.ingest.outputs.status }}}`.
- FR 캐시: `actions/cache@v4`, `path: "[2] db/2) Federal Register/raw"`, `key: fr-raw-${{ github.run_id }}`, `restore-keys: fr-raw-` (캐시는 키별로 한 번만 저장되므로 run_id로 매번 새 키를 만들고 prefix로 복원한다).
- Artifact: `actions/upload-artifact@v4`, `if: steps.ingest.outputs.status == 'new'`. eCFR은 `raw`+`parsed`, FR은 `parsed`만 (raw 653MB는 캐시에 있음). `retention-days: 90`.
- `notify`: `needs: [ecfr, fr]`, `if: always()`. `needs.ecfr.result`(success/failure)와 `needs.ecfr.outputs.status`(new/no_change)로 메시지 조립. slack.yml의 `jq -n --arg text ... | curl` 방식 그대로. 메시지 예:
  - 🟢 `DB 갱신 — eCFR 바뀜 (새 release) · FR 안 바뀜  → RAG 색인 다시 돌릴지 정하세요  <run_url|로그>`
  - ⚪ `DB 갱신 — eCFR 안 바뀜 · FR 안 바뀜`
  - 🔴 `DB 갱신 실패 — fr  <run_url|로그 보기>`
  - 테스트가 보는 글자: `바뀜`, `안 바뀜`, `실패`, `색인` — 전부 `run:` 안에 있어야 한다.
- YAML 테스트는 `yaml.safe_load`로 읽는다. `on:` 키는 True로 읽히니 상관없고, `steps[].uses`가 `actions/cache`·`actions/upload-artifact`로 **시작**해야 한다.

### 4. 사람이 할 일 (Codex가 못 함)
- GitHub → Settings → Secrets → `SUPABASE_URL`, `SUPABASE_SECRET_KEY` 추가 (`.env` 값 그대로)
- PR 브랜치에서 Actions → DB refresh → Run workflow (`workflow_dispatch`는 기본 브랜치에만 뜨므로, main 병합 후 확인해도 됨). Slack에 ⚪ 메시지 오면 완료.
- FR 사이트가 GitHub 러너를 로봇으로 차단하면 `fr` job이 빨강 → 그때 별도 티켓(User-Agent 헤더 등).
