## Codex 메모
- **데이터 모양**은 테스트 파일 맨 위 docstring에 있다. `load_contracts`와 `read_db`는 같은 모양을 돌려준다. 다른 점은 하나다: `not_empty`(YAML에서 옴) 대신 `rows`(DB에서 옴)가 들어간다.
- **`load_contracts(folder)`**
  - `*.odcs.yaml`의 `schema[].properties[]`에서 `physicalType`, `required`, `primaryKey`를 읽는다. 값이 없으면 False로 본다.
  - `not_empty`는 `quality`에 `metric: rowCount`와 `mustBeGreaterThan: 0`이 있으면 True다.
- **`read_db(conn)`** (psycopg, `os.environ["SUPABASE_DB_URL"]`)
  - `public` 스키마의 일반 표만 읽는다 (`pg_class.relkind = 'r'`).
  - 타입은 `format_type(atttypid, atttypmod)`로 읽는다. 그래야 YAML 글자와 같다. 예: `text[]`, `vector(1792)`, `numeric(10,6)`, `timestamp with time zone`.
  - `required`는 `attnotnull`, `primary_key`는 `pg_index.indisprimary`로 읽는다.
  - `rows`는 `select exists(select 1 from <표>)`로 0 또는 1만 구한다. ECHO 표가 수백만 행이라 `count(*)`를 쓰면 느리다.
  - 표 이름은 `psycopg.sql.Identifier`로 감싼다.
- **`compare(expected, actual)`**
  - 오류 글자에 `표` 또는 `표.칸` 이름이 꼭 들어가야 한다 (테스트가 확인한다).
  - 한 가지 차이에 오류 1개만 낸다.
- **명령줄 실행**
  - 오류를 한 줄씩 `::error::...`로 찍고 `exit 1`로 끝낸다.
  - 오류가 없으면 `OK 표 43개 칸 430개`처럼 찍는다.
  - `SUPABASE_DB_URL`이 없으면 조용히 넘어가지 않는다. 이유를 찍고 실패한다.
- **ci.yml**
  - 기존 `tests` job처럼 Python 3.12와 `requirements.txt`를 설치한다.
  - 환경 변수에 `SUPABASE_DB_URL: ${{ secrets.SUPABASE_DB_URL }}`을 넣는다.
  - `timeout-minutes: 5`로 한다.
  - 경로 필터 없이 모든 PR에서 돈다 (검사 한 번이 몇 초면 끝남).
- **Slack**: 새 job은 `CI` workflow 안에 넣는다. 그러면 `slack.yml`이 이미 하는 "🔴 CI 실패" 알림이 그대로 간다. `slack.yml`은 고치지 않는다.
- **사람이 할 일 (merge 전)**: GitHub Secret 등록 `gh secret set SUPABASE_DB_URL` (`.env`의 값). 등록하지 않으면 새 job은 빨간불이 맞다.
- DB에 `fr_diff` 표는 없다(migration 미적용). YAML에도 없어서 서로 맞다. 건드리지 않는다.
- 2026-09-24에 DB 타입 글자를 전부 조회했다. `numeric(10,6)`(`rag_answer_log.cost_usd`)만 빼면 나머지는 모두 YAML `physicalType`과 같다.
