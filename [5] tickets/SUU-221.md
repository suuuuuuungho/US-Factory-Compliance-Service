# SUU-221 feat(db): ADI·Dashboard 목록·PDF를 문서·페이지 jsonl로 만든다

## 목표
SUU-114로 받아둔 raw(목록 HTML 2개 · 상세 details.json · PDF 698건)를 `parsed/{as_of}/adi_source_entry·adi_document·adi_document_version·adi_entry_document·adi_page.jsonl` + `quality_report.json`으로 바꾼다. 성공 + held = 목록 행 수(4,061). 조용히 사라지는 항목 0.

## 건드릴 파일
- 만들 것 (`[2] db/pipeline/4_ADI+CAA/`):
  - `adi_entries.py` — `adi_entry_rows(rows, details_by_control_number, list_sha256) -> list[dict]`, `dashboard_entry_rows(rows, list_sha256) -> list[dict]`, `dashboard_source_key(row) -> str`
  - `adi_documents.py` — `PARSER_VERSION = "1"`, `document_id(sha256) -> str`, `version_id(sha256, parser_version=PARSER_VERSION) -> str`, `build_documents(files, *, reader_factory=None) -> {"adi_document", "adi_document_version", "adi_entry_document", "adi_page", "held"}`
  - `adi_parse.py` — `TABLES`, `parse_all(root, as_of, *, raw_as_of=None, reader_factory=None) -> report`, `main(argv)`: `--root`(기본 `[2] db/4) ADI+CAA`), `--as-of`(기본 오늘), `--raw-as-of`(기본 `root/raw/` 아래 가장 최근 폴더)
- 테스트 (Claude가 씀, Codex 수정 금지): `[2] db/tests/4_ADI+CAA/conftest.py`(`make_pdf` fixture), `test_adi_entries.py`, `test_adi_documents.py`, `test_adi_parse.py`. 기존 fixture `adi_results_sample.html`(39행)·`adi_dashboard_sample.html`(236행) 재사용

## 안 하는 것
- OCR, 본문 해석(질문/답 블록·CFR 인용·관계·시설 후보 → SUU-222)
- 네트워크·재수집. 2005년 이전 ADI 536건과 Part 63 후보가 아닌 행은 PDF가 없으므로 `text_status=text_missing`으로 목록만
- 서명일 확정(`signed_on`은 항상 NULL). 목록 날짜 문자열만 `signed_on_raw`에 보존
- 테이블 생성(SUU-223)·적재(SUU-224). `release_id`·`object_id`는 적재기가 채우므로 jsonl에는 `sha256`/`list_sha256`으로만 원본을 가리킨다
- 기존 수집·텍스트 추출 코드 수정 (`adi_results.py`, `adi_dashboard.py`, `adi_details_parse.py`, `adi_letters_text.py`는 그대로 import해서 쓴다)

## Codex 메모

### 틀
- `[2] db/pipeline/2_Federal Register/fr_parse.py`(SUU-207)와 같은 모양으로 짠다: 정렬 후 jsonl 쓰기, `parsed/{as_of}` 있으면 지우고 다시, 보고서 `status="succeeded"`(held가 있어도 실패 아님), `started_at/finished_at`.
- `pyproject.toml`이 `[2] db/pipeline/4_ADI+CAA`·`1_eCFR`를 pythonpath에 넣어두었다. `from ecfr_raw import save_raw`처럼 flat import.

### 읽는 raw (root = `[2] db/4) ADI+CAA`, raw_as_of = `2026-09-17`)
| 무엇 | 경로 | 여는 법 |
|---|---|---|
| ADI 목록 | `raw/{raw_as_of}/run.json` → `html_sha256` → `raw/{raw_as_of}/{sha}/adi-results.html` | `adi_results.parse_results(html)["rows"]` (3,825행) |
| Dashboard 목록 | `caa_dashboard/raw/{raw_as_of}/run.json` → `html_sha256` → `{sha}/caa-dashboard.html` | `adi_dashboard.parse_dashboard(html)` (236행) |
| ADI 상세 | `adi_details/raw/{raw_as_of}/details.json` — `parse_details` 출력 list(3,813건). 없으면 abstract 전부 None | `{row["control_number"]: row}` |
| ADI PDF | `adi_letters/shard_*/raw/{raw_as_of}/manifest.json` (총 469). `name` = `{control_number}.pdf`, `path`는 shard 폴더 기준 상대경로 | control_number = `name[:-4]` |
| Dashboard PDF | `dashboard_letters/raw/{raw_as_of}/manifest.json` (229). `source_url` = 목록 행의 `canonical_url` | canonical_url로 행 찾기 |
- `raw_as_of` 생략 시 `root/raw/` 아래 이름순 마지막 폴더. 다섯 곳 모두 같은 raw_as_of를 쓴다.
- manifest 항목에 `sha256`이 있다. PDF를 다시 해시할 필요 없음. 같은 sha256이 여러 manifest에 있으면 한 번만 읽는다.

### jsonl 열 (= SUU-223 DDL 열, 이 파일이 원본)
- `adi_source_entry`: `source_system`(adi|caa_dashboard), `source_key`, `control_number`, `facility_name`, `title`, `categories`(list), `office`, `author`, `recipient`(항상 None), `letter_date_raw`, `link_text`, `affected_subpart_raw`, `abstract`, `source_url`, `canonical_url`, `list_sha256`, `scope_status`(part63_candidate|out_of_scope), `text_status`(ok|text_missing|text_failed)
  - ADI: source_key = control_number, canonical_url = source_url, Dashboard 전용 열 None
  - Dashboard: control_number None, categories `[]`, letter_date_raw None(link_text는 날짜가 아니다), source_key = `sha256("\t".join(facility_name, title, affected_subpart_raw, source_url or ""))[:16]`. 한 표에 완전히 같은 행이 두 번 나오면 뒤 행에 `#2`를 붙여 유일하게 만든다
  - scope: ADI는 `set(categories) & {"MACT","NESHAP","GACT"}`, Dashboard는 `"Part 63" in affected_subpart_raw`
- `adi_document`: `document_id` = `uuid5(NAMESPACE_URL, "adi-document:" + sha256)`, `canonical_identity` = `"sha256:" + sha256`
- `adi_document_version`: `version_id` = `uuid5(NAMESPACE_URL, f"adi-version:{sha256}:{parser_version}")`, `document_id`, `sha256`, `signed_on`(None), `signed_on_raw`, `date_source`, `text_content`, `extraction_method`("pypdf"), `parser_version`, `quality_status`, `legal_status`("unknown")
  - `signed_on_raw`/`date_source`: 그 sha256에 붙은 항목 중 `letter_date_raw`가 있는 첫 항목(source_key 정렬)의 값과 `"adi_list"`. 없으면 둘 다 None
  - `text_content` = status ok인 페이지 텍스트를 `"\n\n"`으로 이음. `quality_status`: 전 페이지 ok → `ok`, 일부 empty/failed → `partial`, ok 페이지 0 → `no_text`
- `adi_entry_document`: `source_system`, `source_key`, `version_id`, `match_method`("fetched_from_entry"), `match_status`("확정")
- `adi_page`: `version_id`, `page_no`, `text_content`, `extraction_method`("pypdf"), `ocr_confidence`(None), `status`(ok|empty|failed — `extract_pages`의 status 그대로), `failure_reason`(failed일 때 reason, 아니면 None), `review_status`("검토 전")
- `build_documents(files)`의 `files` 항목: `{"source_system", "source_key", "sha256", "path"(Path), "letter_date_raw"}`. `reader_factory`는 `adi_letters_text.extract_pages`에 그대로 넘긴다(None이면 넘기지 않음)
- held 항목: `{"source_system", "source_key", "sha256", "reason"}`. `PdfReader` 생성이 실패(예: `%PDF` 아님)하면 held. 페이지 단위 실패는 held가 아니라 page.status=failed

### 보고서 `quality_report.json`
`as_of`, `raw_as_of`, `status`, `entries`(목록 행 수), `succeeded`, `held`(list), `files`(manifest PDF 항목 수), `documents`, `details_missing`(상세 없는 ADI 행 수), `rows`({표: 행 수}), `started_at`, `finished_at`. `succeeded` = entries − len(held).

### 주의
- Windows 경로: manifest `path`가 240자를 넘을 수 있다. `ecfr_raw._long_path`를 참고하되 읽기만 하므로 `Path(root / path).read_bytes()`로 충분하면 그대로.
- 정렬: 표마다 `json.dumps(row, sort_keys=True)` 기준 정렬(fr_parse와 동일)해서 재실행 바이트 동일을 맞춘다.
- 실제 데이터 실행은 SUU-225. 이 티켓에서는 tmp_path 테스트만 통과시키면 된다.
