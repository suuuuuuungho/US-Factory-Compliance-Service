# SUU-163 feat(frontend): 질문을 넣으면 후보 Subpart와 판정 기준이 화면에 나온다

## 목표
첫 화면. 질문칸 + Ask 버튼 → `POST {NEXT_PUBLIC_API_URL}/ask` → 로딩 → 후보 Subpart 카드(제목·기준·인용) + 체크리스트. "This is not a final applicability determination" 항상 표시. 디자인 없음, $0.

- 고침: `[4]frontend/src/app/layout.tsx` — `metadata.title`만 "US Factory Compliance"로(선택)

## 완료 기준 ↔ 테스트
| 완료 기준 | 테스트 |

| 응답을 주면 후보마다 `Subpart {code}` + title + 기준 문장 + 인용, 체크리스트 항목이 화면에. 요청은 `POST {NEXT_PUBLIC_API_URL}/ask`, 몸통 `{"question"}` | `가짜 응답을 주면 후보 Subpart·기준·인용·체크리스트가 나온다` |

## Codex 메모

### 응답 모양 (`[3] backend/app/answer.py`, `ecfr_answer.py`)
```ts
export type Criterion = { criterion: string; citations: string[] };
export type Candidate = { subpart: string; title: string; criteria: Criterion[] };
export type AskResult = {
  answer: { candidates: Candidate[]; checklist: string[] } | null;
  sections: { section_key: string; subpart: string }[];
  issues: string[];
  tokens: { prompt: number; completion: number };
  cost_usd: number;
  ms: number;
};
```

### `src/lib/api.ts`
```ts
export async function ask(question: string): Promise<AskResult> {
  const base = process.env.NEXT_PUBLIC_API_URL ?? "http://localhost:8000";  // 호출 시점에 읽는다(테스트가 vi.stubEnv 한다)
  const r = await fetch(`${base}/ask`, { method: "POST", headers: { "content-type": "application/json" }, body: JSON.stringify({ question }) });
  if (!r.ok) throw new Error(`Server error (${r.status})`);
  return r.json();
}
```
- `base`를 모듈 상수로 빼면 테스트의 `vi.stubEnv`가 안 먹는다. 함수 안에서 읽는다
- Render 무료 플랜: 잠들었다 깨면 색인 전까지 `/ask`가 503(SUU-167). 그래서 상태 코드를 화면에 보여준다. 재시도 로직은 안 넣는다

### `src/app/page.tsx`
- `"use client"`. state: `question`, `loading`, `result: AskResult | null`, `error: string | null`
- 폼: `<textarea>` 하나(테스트는 `getByRole("textbox")` — textbox가 **하나**여야 한다) + `<button type="submit">Ask</button>`(이름에 "Ask"). submit 시 `loading=true` → `ask()` → `result` 또는 `error` → `loading=false`. 로딩 중 버튼 `disabled`
- 로딩: `<p role="status">Searching the regulations… (10–20 s)</p>`. 로딩 아닐 땐 **렌더하지 않는다**(테스트가 `queryByRole("status")` null 확인)
- 결과: 후보마다 `<section>` — `<h2>Subpart {subpart} — {title}</h2>`(한 요소에 같이, 테스트는 `/Subpart PPPP/`와 `/Surface Coating/`를 각각 `getByText`로 찾는다 → 둘 다 이 h2에 걸리면 됨), `<ul>` 기준마다 `<li>{criterion} <span>{citations.join(", ")}</span></li>`. 체크리스트 `<h2>Checklist</h2><ul>…`
- `Subpart PPPP` 문자열은 화면에 **한 곳**에만. `sections`는 안 그린다(같은 문자열이 두 번 나오면 `getByText`가 실패)
- `answer === null`이면 `issues`를 `<ul>`로. `error`면 `<p>{error}</p>`
- 항상(맨 아래 고정): `<p>This is not a final applicability determination. The plant decides; this page gives the criteria and where to look.</p>` — 정확한 대소문자 무관, `not a final applicability determination` 포함
- `<main>` 유지(smoke.test.tsx). `next/image`·기본 svg 링크는 지운다(public/*.svg 파일은 놔둔다)
- Next 16 주의: `[4]frontend/AGENTS.md`대로 `node_modules/next/dist/docs/` 확인. App Router 클라이언트 컴포넌트는 그대로 `"use client"`
