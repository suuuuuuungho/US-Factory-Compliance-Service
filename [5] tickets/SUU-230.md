# SUU-230 feat(db): fr_diff 테이블을 만들고 diff JSON을 적재한다

## 목표
SUU-228의 `fr-diff.json`을 Supabase `fr_diff` 표에 넣어, 나중에 API·RAG·판정 로직("이 시설 subpart의 최근 개정")이 `node_key`로 조인해 쓸 수 있게 한다. 프론트(SUU-229)는 그대로 JSON을 읽는다.

## 건드린 파일
- 만듦 `[2] db/migrations/SUU-230_fr_diff.sql` — `fr_diff(release_id, document_key, section, node_key, seq, change_kind, before_text, after_text, is_context, before_date, after_date)`, PK (release_id, document_key, section, seq), FK → fr_document, node_key 인덱스, RLS만 켬
- 만듦 `[2] db/pipeline/2_Federal Register/fr_diff_load.py` — `diff_rows`(JSON → 행), `load_diff`(delete + COPY), CLI `--json --release-id`
- 만듦 `[2] db/tests/2_Federal Register/test_fr_diff_load.py` — 가짜 conn 1개

## 완료 기준 ↔ 테스트
| 완료 기준 | 테스트 |
|---|---|
| 적재 행 수 = JSON의 diff 행 수 | `test_load_diff_copies_every_row_and_skips_documents_without_sections` (count == 4 == rows) |
| 시행일 없는 문서는 fr_diff 행 0개 | 같은 테스트 (document_key 집합에 없음) |

## 실행
```
python "[2] db/pipeline/2_Federal Register/fr_diff_load.py" --json "[4]frontend/public/fr-diff.json" --release-id <fr_document 가 있는 release_id>
```
마이그레이션은 Supabase MCP `apply_migration` 으로 먼저 적용한다.

## 메모
- fr_load(release 파이프라인)에 끼우지 않고 따로 뒀다. diff는 eCFR API를 다시 부르는 별도 단계라 release 적재와 같이 돌리면 느려진다
- 사용자 지시로 Claude가 직접 구현 (Codex 미사용)
