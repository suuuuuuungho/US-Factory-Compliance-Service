# SUU-223 feat(db): adi_ 표 9개를 Supabase에 만든다

## 목표
계획서 3-5절 표 9개(`adi_source_entry`·`adi_document`·`adi_document_version`·`adi_entry_document`·`adi_page`·`adi_block`·`adi_cfr_reference`·`adi_document_relation`·`adi_facility_candidate`)를 Supabase에 만들고 RLS로 외부 노출을 막는다. SUU-221 파서 jsonl과 SUU-224 적재가 이 표를 전제로 한다.

## 건드릴 파일
- 만들 것: `[2] db/migrations/SUU-223_adi_tables.sql` — 적용한 DDL 기록
- Claude가 Supabase MCP(`apply_migration`)로 project `husqnrcuoaogdkbpjnep`에 직접 적용함 (SUU-208과 같은 방식). Codex 작업 아님. 확인은 DB 직접 조회로 대신했다

## 안 하는 것
- 데이터 적재 (SUU-224)
- RLS 정책 (SUU-63과 같이 정책 없이 RLS만 켠다 — service_role만 접근)

## 완료 기준 ↔ 확인 방법
| 완료 기준 | 확인 방법 |
|---|---|
| `adi_` 표 9개, RLS 9개 | `pg_class` 조회 → `relname like 'adi_%'` 9개, `relrowsecurity = true` 9개 |
| `adi_cfr_reference (current_ecfr_release_id, current_node_key) → ecfr_node`, `adi_facility_candidate (echo_release_id, echo_pgm_sys_id) → echo_facility` 복합 FK | `pg_constraint` contype='f' 조회 |
| `adi_document_version (document_id, sha256, parser_version)` 고유 제약 | `adi_document_version_document_id_sha256_parser_version_key` 확인 |

## 적용 결과 (2026-09-22)
- 세 기준 모두 DB 조회로 확인함. 표 9 · RLS 9 · 복합 FK 3(ecfr_node 2: historical/current, echo_facility 1) · 고유 제약 1
- 계획 3-5절에 없지만 SUU-221 파서 키에 맞춰 더한 열: `adi_source_entry.list_sha256`(목록 원본 해시), `adi_page.status`(ok/empty/failed)·`failure_reason`
- `adi_source_entry.source_object_id`, `adi_document_version.object_id`는 nullable FK → `common_raw_object` (SUU-208처럼 적재기가 채움)
- `adi_source_entry.source_system`은 `adi`/`caa_dashboard`만 허용(check). `adi_cfr_reference`의 historical/current eCFR 연결은 둘 다 NULL이거나 둘 다 있어야 함(check)
- 인덱스 13개: control_number, (source_system, source_key), office, document_id, sha256, signed_on, entry_document.version_id, block (version_id, page_no), reference version_id, (title, part, subpart, section), current eCFR 노드, relation to_document_id, facility echo 키
