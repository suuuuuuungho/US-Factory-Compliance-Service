## Codex 메모

### 문서 작성 원칙
- `3_rag 검색 품질 개선 과정.md`와 같은 톤(짧은 한국어, 표 위주, 5살도 읽게). 첫 줄에 한 문단 요약 + 기간.
- 서비스 정의(`[1] docs/1) project/1_project.md`): "최종 판정은 주지 않는다. 어디를 봐야 하고 무엇을 확인해야 하는지를 준다." 답 JSON은 이 약속을 그대로 담는다.

### 1절 `## 1. 답 모양` — JSON 스키마
필드(전부 필수):
```
candidates: [            # 후보 Subpart. 검색 상위 조문에서 나온 것만. 1~3개
  { subpart: "PPPP",     # Subpart 코드
    title: "...",        # Subpart 이름
    criteria: [          # 적용 여부를 가르는 기준. 1개 이상
      { criterion: "...",        # 한 문장. "~이면 적용 / ~이면 미적용"
        citations: ["40 CFR 63.4481(a)"] } ] } ]   # 넘겨준 조문 안에서만. 1개 이상
checklist: ["..."]       # 공장이 확인할 것. 1개 이상
```
- `applies`, `verdict`, `conclusion` 같은 최종 판정 필드는 **없다**.
- 예시 1건은 평가셋 `rag_eval_case_v2.jsonl` 첫 케이스(`dashboard-king-systems-2020-06-16`, PPPP, MeCl 용제 접합)로 쓴다. 인용은 그 케이스 `gold_citations`에서.
- 예시 블록은 반드시 ```json 으로 시작해야 테스트가 파싱한다. 주석 없이 순수 JSON.

### 2절 `## 2. 채점표` — 표 하나
| 지표 | 무엇 | 계산 | 비용 |
|---|---|---|---|
| Subpart 적중 | 답의 `candidates[].subpart`에 `gold_subparts[0]`이 있나 | 0/1, 케이스 평균 | $0 |
| 인용 Recall | `gold_citations`(조문 단위, 문단 번호 뗌) 중 답의 `citations`에 나온 비율 | 케이스 평균 | $0 |
| 인용 근거율 | 답의 `citations`가 넘겨준 조문(상위 5) 안에 있는 비율. 밖이면 "지어냄" | 케이스 평균 | $0 |
| **판정 기준 점수**(주 지표) | gpt-5-mini 심판이 답의 `criteria`를 EPA `notes`와 비교 | 0·1·2점(0 틀림 / 1 부분 / 2 맞음), 케이스 평균 → 0~2 | ~$0.3/102건 |
- 조문 단위 비교 규칙은 검색과 같다(`rag_eval_plan.md` [3]-1: `40 CFR 63.4481(a)(1)` → `section-63.4481`).
- 심판 프롬프트에 들어갈 것: 질문, 답 JSON, `notes`. 심판은 "notes의 판단 근거가 criteria에 담겼는가"만 본다. 최종 결론 일치 여부는 안 본다(답에 결론이 없으므로).
- 심판 신뢰는 SUU-148에서 사람이 10건 검증.

### 3절 `## 3. 동점 폭`
- 판정 기준 점수 0.06 미만 차이(≈ 102건 중 3건이 한 단계 바뀐 양) = 동점. 검색의 0.03과 같은 논리(3건).
- $0 지표 3개는 0.03 미만 = 동점.
