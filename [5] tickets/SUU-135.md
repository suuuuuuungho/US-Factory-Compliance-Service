# SUU-135 chore(rag): OpenAI로 상위 20조문을 다시 줄 세워 nDCG를 잰다

## 목표
저장된 Kanon hybrid 순위(`ranked_all`)에 규칙(SUU-134)을 적용한 뒤 상위 20조문(조문당 앞 3,000자)을 질문과 함께 OpenAI LLM에 보내 다시 줄 세우고, v2 102건을 채점해 LLM 리랭크가 남은 손실(창 20 천장 0.866 vs 0.631)을 얼마나 가져가는지 잰다. Kanon 재실행 없음, Supabase 읽기만.

## 건드린 파일
- 만듦: `[6] rag/eval/llm_rerank.py` — `ruled_sections`/`top_sections`(규칙 후 상위 20), `build_rerank_prompt`, `parse_ranking`(후보 번호 → 키, 빠진 키는 원래 순서로 뒤에), `rerank_line`, `fetch_heads`(캐시 `cache/section_heads.json`), `scoreboard`. `--model`, `--limit`
- 만듦: `results/2026-09-18_hybrid_v2_llm_gpt-4o-mini.jsonl`, `results/2026-09-18_hybrid_v2_llm_gpt-5-mini.jsonl`, `[6] rag/tests/test_llm_rerank.py`
- 고침: `results/rag_eval_result.md`(SUU-135 절), `rag_eval_plan.md` [9]·[14], `[1] docs/3) rag/3_rag 품질 개선 과정.md`

## 안 하는 것
- `search_sections`에 LLM 리랭크 넣기(결과 보고 결정), Kanon 재실행, Anthropic API, Supabase 쓰기, 조문 전문 보내기(3,000자 잘라 보냄)

## 완료 기준 ↔ 테스트
| 완료 기준 | 테스트 함수 |
|---|---|
| 프롬프트에 질문과 20개 조문 키·본문(3,000자 이내) | `test_prompt_has_question_and_truncated_sections` |
| 답의 후보 번호(또는 키) 순서로 정렬, 빠진 키는 원래 순서로 뒤에 | `test_parse_ranking_fills_missing_keys` |
| LLM이 순서를 안 바꾸면 hybrid+규칙과 같은 0.631 | `test_identity_rerank_keeps_score` |

## 결과
- **gpt-5-mini: nDCG@10 0.631 → 0.692(+0.061)**, Hit@5 0.882 → 0.931, Hit@20·Recall@20 불변(20개 안에서만 재정렬). 좋아짐 49 / 나빠짐 24 / 같음 29. v1·새 70·dashboard 모두 같은 방향. $0.58, 3분 40초(8병렬), ≈ 20초/건.
- gpt-4o-mini: 0.645(+0.014, 동점). 1등을 42건 바꿨지만 상쇄. $0.17.
- miss@20 4건 그대로. 프롬프트 ≈ 10.5k 토큰/건.
