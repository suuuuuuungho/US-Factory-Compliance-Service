# SUU-258 feat(frontend): Decision Letter 페이지에서 공장 설명으로 유사 사례 검색

## 목표
/decision-letter 위에 공장 설명 글칸 + Search. 결과가 오면 표가 비슷한 서한(최대 5건, score·snippet 포함)으로 바뀌고, 빈 배열이면 표 대신 안내 문구, Clear 면 132건 목록으로 복귀.

## 건드릴 파일
- 고칠 것: `[4]frontend/src/lib/api.ts`
  - `export type SimilarLetter = Letter 메타 6개 + { score: number; snippet: string }`
  - `export async function similarLetters(description: string): Promise<SimilarLetter[]>` — `POST {NEXT_PUBLIC_API_URL}/letters/similar` body `{description}`, 응답 `{letters}` 의 `letters` 를 돌려준다. `ask()` 와 같은 모양(base 는 호출 시점에 읽기, `!r.ok` 면 throw)
- 고칠 것: `[4]frontend/src/app/decision-letter/page.tsx`
  - 제목 아래 `<textarea aria-label="Factory description">` + `Search` 버튼 + `Clear` 버튼
  - 상태 `results: SimilarLetter[] | null` (null = 검색 안 한 상태 → 132건 표), `loading: boolean`
  - Search → `similarLetters(description)` → `results` 에 넣음. 로딩 중 Search 버튼 `disabled`
  - `results` 가 배열이면 표는 그 건수만 (페이지 자르기 없음), 행마다 `Score` 열(`score.toFixed(2)`)과 제목 아래 `snippet` 표시. 페이지 바(Prev/Next)는 숨김
  - `results` 가 `[]` 이면 `<table>` 대신 문구 한 줄 (아래 "안내 문구" 그대로)
  - Clear → `results = null`, 글칸 비움, `page = 0` → 원래 132건 표(10개씩, 1 / 14)
  - 실패(throw) 시 기존 `error` 상태 재사용 → "불러오지 못했습니다."

## Codex 메모
- 백엔드는 merge 됨(#238, SUU-257). `POST /letters/similar {description}` → `{"letters": [{source_key, facility_name, title, subparts, date, pdf_url, score, snippet}, ...]}`. 이미 점수 내림차순·최대 5건이라 프론트에서 다시 정렬·자르지 않는다. 빈 description 은 422 이므로 글칸이 공백이면 Search 를 안 보내도 된다(버튼 disabled 로 처리해도 됨; 테스트는 안 봄)
- 테스트는 `fetch` 를 통째로 가짜로 바꾸고 URL 이 `/letters/similar` 로 끝나는지로 구분한다. 즉 `similarLetters` 도 전역 `fetch` 를 써야 하고 `decision-letters.json` 읽기도 그대로 둔다
- 안내 문구는 글자까지 똑같이:
  `No similar cases found. Letters with weak similarity are not recommended, to keep results trustworthy. Try describing your process, fuel, or equipment.`
  한 요소 안에 통째로 넣는다(`getByText` 가 정확히 맞춰 찾는다)
- score 는 `toFixed(2)` 로 셀 하나에 (`0.91`), snippet 도 요소 하나에 그대로(`getByText` 정확 일치). 테스트는 `within(row)` 로 행 안에서 찾으므로 둘 다 `<tr>` 안에 있어야 한다
- 글칸 접근 이름은 `Factory description` (`aria-label`), 버튼 텍스트는 `Search` / `Clear`. `screen.getByRole("textbox", {name})` 으로 찾는다
- 표 열은 기존 6개(#, Facility, Title, Subpart, Date, PDF)에 검색 모드일 때만 `Score` 열을 붙이면 된다. 검색 모드에서 `#` 은 1부터
- 기존 테스트 `decision_letter_list.test.tsx`, `decision_letter_col_width.test.tsx` 도 계속 초록이어야 한다. 그 테스트들은 `fetch` 가 URL 을 안 가리고 `{letters}` 를 주므로, 처음 렌더에서 `/letters/similar` 를 부르면 안 된다
- 실행: `[4]frontend` 에서 `npm test`
