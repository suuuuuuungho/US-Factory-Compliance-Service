# SUU-255 feat(frontend): Save as PDF 버튼으로 편지와 메모를 내려받음

## 목표
답이 오면 "Save as PDF" 버튼이 생기고, 누르면 편지 `.pdf`가 내려받아진다. 메모칸에 쓴 제목·본문은 편지 끝 Notes 절에 들어간다.

## 건드릴 파일
- 고칠 것: `[4]frontend/src/app/applicability/page.tsx` — `result`가 있을 때 "Save as PDF" 버튼. 클릭 시 `pdf(<LetterPdf question result memo />).toBlob()` → `URL.createObjectURL` → `<a download="applicability-letter-YYYY-MM-DD.pdf">` 만들고 `a.click()`. 메모 state(`title`, `body`)를 page가 들고 있는다
- 고칠 것: `[4]frontend/src/app/MemoPane.tsx` — `onChange?: (title: string, body: string) => void` prop 추가. 편집칸 입력이 바뀔 때마다(기록 항목을 눌러 불러올 때 포함) 부른다
- 고칠 것: `[4]frontend/src/app/applicability/LetterPdf.tsx` — `memo?: { title: string; body: string }` prop 추가. 제목이나 본문 중 하나라도 있으면 Related Sections 뒤에 `Notes` heading + 제목 + 본문. 둘 다 비어 있거나 memo가 없으면 Notes 절 자체를 그리지 않는다

## 안 하는 것
- 저장된 메모 기록(localStorage 목록) 전체 포함 안 함. 지금 편집칸에 있는 글만
- 서버 저장·업로드 없음. 백엔드 변경 없음
- `tests/` 아래 수정 금지

## Codex 메모
- 테스트는 `@react-pdf/renderer`를 vi.mock으로 바꾼다. export는 `Document/Page/View/Text/StyleSheet/pdf` 여섯 개뿐이다. **이 외의 것(Font, Image, PDFDownloadLink, usePDF 등)은 쓰지 않는다.** 특히 `PDFDownloadLink`/`usePDF` 대신 반드시 `pdf(element).toBlob()`을 쓴다.
- 테스트의 가짜 `pdf(el)`은 넘겨받은 `<LetterPdf …/>` 요소를 잡아둔 뒤 다시 렌더해 글자를 본다. 그래서 `pdf()`에 넘기는 요소는 **`<LetterPdf question={…} result={result} memo={…} />` 그대로**여야 한다 (Document로 한 번 더 감싸거나 다른 컴포넌트로 싸지 않는다).
- 다운로드는 `const a = document.createElement("a"); a.href = URL.createObjectURL(blob); a.download = \`applicability-letter-${yyyy-mm-dd}.pdf\`; a.click(); URL.revokeObjectURL(a.href)`. 테스트가 `HTMLAnchorElement.prototype.click`을 가로채 `a.download`를 본다. `window.open`이나 `location.href` 는 쓰지 않는다.
- 날짜는 로컬 날짜로 `YYYY-MM-DD` (예: `new Date().toISOString().slice(0,10)` 도 정규식은 통과한다).
- `@react-pdf/renderer`를 page.tsx 최상단에서 static import 하면 Next 서버 렌더·jsdom 기존 테스트(`memo_pane.test.tsx` 등, mock 없음)가 깨질 수 있다. 안전하게 **클릭 핸들러 안에서 `const [{ pdf }, { LetterPdf }] = await Promise.all([import("@react-pdf/renderer"), import("./LetterPdf")])`** 로 동적 import 한다. vitest의 vi.mock은 동적 import에도 적용된다.
- 버튼 이름은 정확히 `Save as PDF` (`getByRole("button", { name: "Save as PDF" })`). 위치는 Question 칸(form/status 옆) 이면 된다. `answer`가 null(issues만 온 경우)일 때는 버튼을 숨겨도 되고 보여도 된다 — 테스트는 answer가 있는 경우만 본다.
- MemoPane: `title`/`body` setState 하는 곳마다 `onChange?.(nextTitle, nextBody)`를 함께 부른다 (input onChange, textarea onChange, 기록 항목 클릭). 기존 localStorage 저장 동작은 그대로.
- LetterPdf Notes 절: `Text style={s.heading}` 으로 `Notes`, 그 아래 제목(있으면 `Times-Bold`), 본문. 본문 줄바꿈은 `Text`가 `\n`을 그대로 그린다. 조건: `memo && (memo.title.trim() || memo.body.trim())`.
- 기존 letter_pdf 테스트의 mock에는 `pdf`가 없다 → LetterPdf.tsx 안에서 `pdf`를 import 하지 않는다 (page.tsx에서만).
- 실행: `[4]frontend`에서 `npm test`. 기존 테스트도 모두 초록이어야 한다.
