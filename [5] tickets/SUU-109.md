## Codex 메모

테스트가 부르는 것:

```python
def violation_rows(row: dict[str, str]) -> tuple[dict, dict]
```

- 실제 헤더 16열 (2026-09-17 ZIP): `PGM_SYS_ID, ACTIVITY_ID, AGENCY_TYPE_DESC, STATE_CODE, AIR_LCON_CODE, COMP_DETERMINATION_UID, ENF_RESPONSE_POLICY_CODE, PROGRAM_CODES, PROGRAM_DESCS, POLLUTANT_CODES, POLLUTANT_DESCS, EARLIEST_FRV_DETERM_DATE, HPV_DAYZERO_DATE, HPV_RESOLVED_DATE, DSCV_PATHWAY_DATE, NFTC_PATHWAY_DATE`.
  - 102,675행, `ACTIVITY_ID` 중복 1행. 날짜 5열은 전부 `MM-DD-YYYY` (다른 파일과 다름 — `parse_date`가 둘 다 받는다). 빈 날짜 많음 (FRV 위반은 `HPV_DAYZERO_DATE`가 비는 게 정상).
  - `POLLUTANT_CODES`는 전부 숫자 코드 공백 구분 (`7003 300000319 300000329`). `PROGRAM_CODES`도 공백 구분 (`CAANSPS CAASIP`). `*_DESCS`는 설명이 공백으로 이어 붙어 못 쪼갠다 → 원문 그대로.
- violation 키 순서 (테스트가 dict 통째 `==`):
  `violation_id, determination_uid, policy_code, agency, state, first_frv_date, hpv_dayzero_date, resolved_date, programs, pollutants, raw_dates, attributes`
  - `violation_id` ← `ACTIVITY_ID` (없으면 KeyError 그대로)
  - `determination_uid` ← `COMP_DETERMINATION_UID`, `policy_code` ← `ENF_RESPONSE_POLICY_CODE`, `agency` ← `AGENCY_TYPE_DESC`, `state` ← `STATE_CODE`. 넷 다 `""`→None (`is_missing`)
  - `first_frv_date` ← `parse_date(EARLIEST_FRV_DETERM_DATE)`, `hpv_dayzero_date` ← `HPV_DAYZERO_DATE`, `resolved_date` ← `HPV_RESOLVED_DATE`
  - `programs` ← `split_codes(PROGRAM_CODES)`, `pollutants` ← `split_codes(POLLUTANT_CODES)`
  - `raw_dates` = 날짜 5열 `{열이름: 원문}` (`""`도 `""`), 순서 `EARLIEST_FRV_DETERM_DATE, HPV_DAYZERO_DATE, HPV_RESOLVED_DATE, DSCV_PATHWAY_DATE, NFTC_PATHWAY_DATE`
  - `attributes` = `{"AIR_LCON_CODE", "PROGRAM_DESCS", "POLLUTANT_DESCS"}` 값 `""`→None. (계획 문서 `echo_violation` 열엔 없던 것 — 세 열을 버리지 않으려고 jsonb 하나 추가. SUU-111/Step 3에서 열로 반영)
- link = `{"violation_id": row["ACTIVITY_ID"], "pgm_sys_id": row["PGM_SYS_ID"]}`.
- `strip()` 안 함. 표준 라이브러리만, 40줄 안팎. `from echo_values import is_missing, parse_date, split_codes` (평면 import — `echo_facility.py`와 같은 방식).
