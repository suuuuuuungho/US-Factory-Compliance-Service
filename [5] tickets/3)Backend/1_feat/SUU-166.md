# SUU-166 feat(backend): 벡터 검색을 pgvector로 옮겨 임베딩을 서버에서 뺀다

## Codex 메모

### `SUU-166_match_rag_chunk.sql`
```sql
-- SUU-166: 질문 벡터와 가까운 청크 k개. 서버가 임베딩을 안 들고 있으려고 DB에서 계산한다.
-- 5,625행이라 인덱스 없이 정확 계산(수십 ms). score = 코사인 유사도 = 1 - 거리. ecfr_index_run.rank_chunks_by_similarity와 같은 값.

create or replace function match_rag_chunk(query_embedding vector(1792), p_release_id uuid, k integer)
returns table (chunk_key text, score double precision)
language sql stable
as $$
    select chunk_key, 1 - (embedding <=> query_embedding) as score
    from rag_chunk
    where release_id = p_release_id and index_status = 'embedded'
    order by embedding <=> query_embedding
    limit k
$$;
```
- 테스트는 공백을 하나로 합치고 소문자로 만든 뒤 위 문자열들을 찾는다. 이 모양 그대로면 통과
- 인자 이름 `p_release_id`는 컬럼 `release_id`와 겹치지 않게 한 것. `k`는 그대로

### `ecfr_search.py`
- 시그니처에 `vector: Callable[[list[float], int], list[dict[str, Any]]] | None = None` 추가(`llm` 뒤)
- `ecfr_search.py:97-100`의 `vector_chunks = rank_chunks_by_similarity(query_embedding, chunks, top_k=chunk_top_k)`를
  `vector_chunks = vector(query_embedding, chunk_top_k) if vector is not None else rank_chunks_by_similarity(...)`로
- 나머지(RRF·rerank·rules·llm)는 손대지 않는다. `vector`가 돌려주는 항목은 `chunk_key`·`node_key`·`chunk_text`·`score`가 있는 청크 dict(메모리 청크 + score)
- docstring에 한 줄: `vector` (query_embedding, k) -> scored chunks replaces the in-memory cosine ranking

### `index.py`
- `columns = "chunk_key,node_key,context_text,chunk_text"` (embedding 뺌). `json.loads` 줄과 `import json` 삭제
- `Index`에 `vector: Callable[[list[float], int], list[dict]] | None = None` 필드(마지막). `test_main.py`가 세 인자로 만든다
- `load_index`에서:
  ```python
  by_key = {c["chunk_key"]: c for c in chunks}
  def vector(query_embedding, k):
      rows = client.rpc("match_rag_chunk", {"query_embedding": query_embedding, "p_release_id": release_id, "k": k}).execute().data
      return [{**by_key[r["chunk_key"]], "score": r["score"]} for r in rows if r["chunk_key"] in by_key]
  _CACHE[release_id] = Index(release_id, chunks, build_keyword_search(chunks), vector)
  ```
- `FakeSupabase`는 `table().select().eq().eq().order().range().execute()`와 `rpc(name, params).execute()`만 흉내낸다. `select`는 컬럼 문자열 하나를 받는다
- supabase-py: `client.rpc("match_rag_chunk", {...})`에 파이썬 리스트를 넘기면 pgvector가 받는다(Supabase 문서 `match_documents` 패턴과 같다)
