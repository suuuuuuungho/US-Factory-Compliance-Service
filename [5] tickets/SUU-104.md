# SUU-104 feat(db): 공식 Subpart 사전을 받아 code_map 파일로 만든다

## 목표
EPA 사전 페이지 HTML의 표를 읽어 `CAAMACT6J → 40 CFR Part 63 Subpart JJJJJJ` 행을 만들고 `code_map/{version}/echo_code_map.jsonl`로 저장한다.

## 건드릴 파일
- 만들 것: `[2] db/pipeline/3_ECHO/echo_codemap.py`
- 이미 있음 (수정 금지): `[2] db/tests/3_ECHO/test_echo_codemap.py`

## 안 하는 것
- 실제 페이지 다운로드 (SUU-112에서 `echo_fetch.fetch_to_file`로 받는다) — 이 모듈은 HTML 문자열만 받는다
- 코드 문자열에서 Subpart 추측 (`CAAMACT6J`의 `6J`를 `JJJJJJ`로 바꾸는 규칙 등). Subpart는 **설명 문장에서만** 읽는다
- Part 63 이외 사전 검증, `tests/` 수정

## 완료 기준 ↔ 테스트
| 완료 기준 | 테스트 함수 |
|---|---|
| 페이지 안 모든 표를 읽어 행마다 `program_code, raw_subpart_code, raw_description, cfr_title, cfr_part, cfr_subpart, review_status, dictionary_version, source_url` 9키. HTML 엔티티(`&amp;`)는 풀린다 | `test_rows_from_all_tables_with_cfr_fields_filled` |
| 설명에 `Part n - Subpart X`가 없으면 `cfr_*` 셋 다 `None` + `"unresolved"`. 같은 `raw_subpart_code`가 다른 설명으로 또 나오면 그 행들 전부 `"conflict"`. 행은 버리지 않는다 | `test_unresolved_when_no_part_subpart_and_conflict_when_same_code_differs` |
| `write_code_map(root, version, rows)` → `root/code_map/{version}/echo_code_map.jsonl`, 한 줄 = 한 행, 경로 반환 | `test_write_code_map_puts_jsonl_under_code_map_version` |

## Codex 메모

테스트가 부르는 것:

```python
def parse_code_table(html: str, *, version: str, source_url: str) -> list[dict]
def write_code_map(root: Path, version: str, rows: list[dict]) -> Path
```

- 실제 페이지 (2026-09-17 확인, 113KB): `<table>` 4개(GHG·MACT·NESHAP·NSPS), 머리글 `Program Code | Program Subpart | Code Description`, 데이터 306행. 설명은 `MACT Part 63 - Subpart JJJJJJ - 이름`, `NSPS Part 60 - Subpart A - ...`, `GHG Part 98 - ...`, `NESHAP Part 61 - ...` 꼴.
- 실제로 깨진 행 7개: Subpart 칸이 `CAAMACT`뿐이고 설명이 `6B MACT Part 63 - Subpart BBBBBB - ...`로 시작. 그래서 `CAAMACT`가 7번 다른 설명으로 나온다 → 전부 `conflict`. 고치려 들지 말 것.
- 파싱: 표준 라이브러리 `html.parser.HTMLParser`로 `<table>`·`<tr>`·`<td>` 추적, `<th>` 행은 버린다. 텍스트는 `handle_data` 누적 후 `strip()`. `HTMLParser`는 `&amp;` 같은 엔티티를 기본으로 풀어준다(`convert_charrefs=True`). 정규식으로 `<td>` 뽑아도 되지만 그때는 `html.unescape` 필수.
- CFR: `re.search(r"Part (\d+) - Subpart ([A-Za-z0-9]+)", description)` → `cfr_title="40"`(고정), `cfr_part`, `cfr_subpart`. 못 찾으면 셋 다 `None`. 문자열로 둔다(숫자 변환 안 함).
- `review_status` 순서: 같은 `raw_subpart_code`에 설명이 2가지 이상 → `"conflict"` (cfr 파싱 성공 여부와 무관) / 아니면 cfr 못 읽음 → `"unresolved"` / 아니면 `"ok"`. 두 번 훑는다: 1차로 `code → {descriptions}` 모으고 2차로 상태 매긴다.
- 행 순서는 페이지 순서 그대로. 딕셔너리 키 순서는 위 9개 순서(테스트가 `==`로 통째 비교).
- 저장: `path.parent.mkdir(parents=True, exist_ok=True)`, `json.dumps(row, ensure_ascii=False)` 한 줄씩 + `"\n"`, `encoding="utf-8"`. 표준 라이브러리만, 60줄 안팎.
