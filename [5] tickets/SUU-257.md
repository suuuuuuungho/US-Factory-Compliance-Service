# SUU-257 feat(backend): 공장 설명 입력 시 유사 판정서한 상위 5건 반환

## 목표
`POST /letters/similar {description}` → 충분히 비슷한 판정서한만 최대 5건, 서한마다 최고 리랭커 점수 1개 + 메타(시설명·제목·subpart·날짜·PDF) + 근거 문장.

## 건드릴 파일
- 만들 것: `[3] backend/app/letters.py`
  - `LETTER_RELEASE_ID = "5cc370d0-c513-4376-981f-2d910b39ae6b"` (SUU-256이 서한 청크를 넣는 adi release)
  - `MIN_SCORE = 0.03` — 리랭커 점수(0~1) 기준선. 근거는 아래 "MIN_SCORE 근거"
  - `TOP_N = 5`, `RERANK_K = 20`
  - `source_key_of_chunk(chunk) -> str` — `chunk_key = "dashboard/{source_key}/{n}"` 에서 가운데
  - `load_letter_meta(path=...) -> dict[str, dict]` — `[4]frontend/public/decision-letters.json` 의 `letters[]` 를 source_key 로 색인
  - `similar_letters(description, *, index, embed, rerank, meta) -> list[dict]`
- 고칠 것: `[3] backend/app/main.py`
  - `STATE["letters"]`(서한 Index), `STATE["letter_meta"]` 추가. `_load()`에서 eCFR 색인 뒤에 `load_index(client, LETTER_RELEASE_ID)` + `load_letter_meta()` 로 채운다
  - `POST /letters/similar` — body `{description: str}`. 준비 전 503, 빈(공백만) description 422, 정상 `{"letters": [...]}`

## Codex 메모
- SUU-256 은 merge 됐다(#237). 서한 청크 `rag_chunk` release `5cc370d0-…`, `index_status = "embedded"` 라 `load_index` 가 그대로 읽는다.
- `similar_letters` 순서 (`ecfr_search.search_sections` 의 앞부분과 같게, 규칙·LLM 은 뺀다):
  1. `emb = embed(build_query_embedding_request(description))` (`ecfr_eval`)
  2. `vector_chunks = index.vector(emb, CHUNK_TOP_K)` — `index.vector` 가 None 이면 `rank_chunks_by_similarity(emb, index.chunks, top_k=…)` (`ecfr_index_run`). CHUNK_TOP_K 는 `app.answer.CHUNK_TOP_K`(150) 재사용
  3. `keyword_chunks` = `index.keyword(description, CHUNK_TOP_K)` 의 chunk_key 를 `index.chunks` 에서 찾아 붙인다 (search_sections 와 같은 코드)
  4. `ranked = rrf_merge([vector_chunks, keyword_chunks])[:RERANK_K]` (`ecfr_search.rrf_merge`)
  5. `scores = rerank(description, ranked)` → 각 청크에 `score`
  6. source_key 별로 최고 score 청크 하나만 남긴다 → `score < MIN_SCORE` 제거 → `(-score, source_key)` 정렬 → `[:TOP_N]`
  7. 한 건 = `{**meta[source_key], "score": score, "snippet": best_chunk["chunk_text"]}`. meta 에 없는 source_key 는 건너뛴다
- `rerank` 인자 모양은 `/ask` 와 같다: `lambda q, chunks: call_isaacus_rerank_api(build_rerank_request(q, chunks))["scores"]`. `embed` 는 `call_kanon2_api`
- Index 는 `app.index.load_index` 그대로 (`_CACHE` 가 release_id 별이라 eCFR 과 안 섞인다). `load_index` 는 `index_status == "embedded"` 만 가져오니 SUU-256 이 그 값을 쓰는지 확인
- `load_letter_meta` 기본 경로: `Path(__file__).resolve().parents[3] / "[4]frontend" / "public" / "decision-letters.json"` (Render 는 레포 루트에서 돈다, `render.yaml` 참고)
- 422: pydantic `field_validator("description")` 에서 `strip()` 이 빈 문자열이면 `ValueError` → FastAPI 가 422 로 바꾼다. `/ask` 의 400 과 다르다는 점 주의 (티켓이 422 를 요구)
- `_load()` 는 스레드에서 돈다. eCFR `STATE["index"]` 를 먼저 채우고 그 뒤에 서한 색인을 채운다 (`/ask` 준비가 늦어지지 않게)
- 테스트 실행: 레포 루트에서 `python -m pytest` (`-k letters` 로 이 파일만). 파일 경로 지정은 `[]` 때문에 안 된다

### MIN_SCORE 근거 (2026-09-22, 실제 128건 청크로 잰 값)
`벡터+BM25 → RRF 상위 20 → Kanon 리랭커` 를 돌려 서한별 최고 점수를 봤다.

| 질문 종류 | 1등 점수 | 2등 |
|---|---|---|
| 실제 서한과 같은 사례 3개 (플라스틱 solvent welding / perc 세탁소 / RICE 원격 엔진) | 0.906 / 0.926 / 0.708 | ≤ 0.004 |
| 같은 업종, 다른 질문 2개 (크라프트 펄프 / 보일러 대체 모니터링) | 0.053 (Domtar, S) / 0.135 (Shuqualak, DDDDD), 0.071 (Foley, DDDDD) | |
| 무관 3개 (신발 판매 / 소프트웨어 / 식당) | 0.001 / 0.000 / 0.002 | |

- 처음엔 0.05 로 했으나 구현 후 실제 호출에서 펄프 질문이 말투에 따라 Domtar 0.053 / 0.044 로 경계에 걸림 → **0.03** 으로 내림
- **0.03**: 같은 업종 사례를 안정적으로 살리고, Westvaco(0.02)·무관 최고점(0.002, 15배 여유)은 탈락
- 0.3 이상이면 거의 같은 사례만 남아 "비슷한 사례" 용도로 너무 좁다
- 값을 바꿀 때는 이 표를 다시 재고 여기와 `letters.py` 주석을 같이 고친다
