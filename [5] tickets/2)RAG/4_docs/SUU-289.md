# SUU-289 docs(rag): 프로젝트 문서를 절별로 나누고 docs README 추가

## 왜
`1_Project_full.md` 한 파일이 590줄이라 원하는 절을 찾기 어렵다.
절 단위 파일과 안내서(README)가 있으면 처음 온 사람도 바로 찾는다.

## 변경 범위
`[1] docs/` 아래만.

- `1_Project_full.md`를 절 단위로 복사해 파일 5개 생성. 원본은 그대로 둔다.
  - `2_Project_overview.md` 소개·어필 포인트·기간·흐름·기술 스택 (원본 1~90줄)
  - `3_Project_problem_definition.md` 문제 정의·활용한 데이터셋 (원본 92~340줄에서 판단 사항 절 제외)
  - `4_Project_rag_quality.md` RAG 검색·답변 품질 개선 (원본 342~508줄)
  - `5_Project_tdd_automation.md` TDD 개발 자동화 (원본 512~590줄)
  - `6_Project_my_decisions.md` 직접 정한 판단 사항 (3번 파일에서 잘라 옮김)
- `[1] docs/README.md` 신규. project 문서 7개, Data Specification, ODCS 계약서 6개와 검사 스크립트의 역할을 표로 정리.
- 사용자가 직접 고친 `0_Project_summary.md`, `1_Project_full.md`, `0_Data Specification_v1.md` 변경도 함께 포함.

## 완료 기준
- 나눈 파일 5개 내용이 원본 해당 절과 글자까지 같다.
- 코드·테스트 변경 없음. 기존 `python -m pytest` 전부 통과.
