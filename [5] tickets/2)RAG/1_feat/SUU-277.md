# SUU-277 feat(rag): 관문 답 출력 상한 올려 51건 재실행

답 요청의 출력 토큰 상한(`max_completion_tokens`)을 호출마다 올릴 수 있게 하고, 관문(gates) 답을 상한 20,000으로 선별셋 51건에 한 번 더 돌려 빈 답 없이 `answer_runs.jsonl`에 남긴다. 코드 조금 + 실제 run 1개(≈$1.2).

## Codex 메모

### 왜
SUU-275 관문 run은 51건 중 10건이 빈 답이다. 열 건 모두 `raw_answer == ""`, `completion_tokens == 10000` = `MAX_COMPLETION_TOKENS`. gpt-5-mini는 추론 토큰이 `max_completion_tokens`에 포함되므로 생각만 하다 상한을 다 쓴 것이다. 파싱된 41건은 밖 인용 0건. 답 모양이 아니라 예산 문제.

### `ecfr_answer.py`
- `build_answer_request(question, sections, *, model=ANSWER_MODEL, shape="criteria", max_completion_tokens=MAX_COMPLETION_TOKENS)`. 요청 dict의 `"max_completion_tokens"`에 그 값을 넣는 것뿐. 나머지(메시지·모델)는 그대로.

### `run_answer.py`
- `default_run_id(shape: str, model: str, *, subset: bool, max_completion_tokens: int, day: str | None = None) -> str`
  - `day`가 None이면 `f"{datetime.now(timezone.utc):%Y-%m-%d}"`.
  - `f"{day}_answer_{shape}_{model}"` + (`"_subset51"` if subset) + (`f"_out{max_completion_tokens // 1000}k"` if `max_completion_tokens != MAX_COMPLETION_TOKENS`). `MAX_COMPLETION_TOKENS`는 `ecfr_answer`에서 import.
  - `main()`의 인라인 run_id 계산을 이 함수로 바꾼다.
- `argparse`: `--max-completion-tokens` (type int, default `MAX_COMPLETION_TOKENS`). `one()` 안의 `build_answer_request(...)` 호출에 `max_completion_tokens=args.max_completion_tokens`를 넘긴다. replay/retry 재사용 경로는 그대로.
- `answer_run_record(..., max_completion_tokens: int = MAX_COMPLETION_TOKENS)` → 기록 dict에 `"max_completion_tokens"` 키. 기존 키 순서·이름은 건드리지 않는다. `main()`에서 `max_completion_tokens=args.max_completion_tokens`로 넘긴다.
- 옛 run 줄에는 이 키가 없다. 테스트는 없으면 10,000으로 본다. 옛 줄에 키를 채워 넣지 않는다.

### 돌리기
```
python "[6] rag/eval/run_answer.py" --shape gates --subset --max-completion-tokens 20000
python "[6] rag/eval/answer_failures.py" --run-id <새 run_id>
```
- 새 run_id는 `<오늘>_answer_gates_gpt-5-mini_subset51_out20k`.
- 끝나면 `no answer: []`여야 한다. 그래도 빈 답이 있으면 `--retry-empty --run-id <같은 id> --max-completion-tokens 20000`으로 빈 것만 다시(있는 답은 재사용). 그래도 남으면 멈추고 사용자에게 보고. 상한을 더 올리지 않는다.
- 커밋: 코드 2 + 결과 파일 1 + `answer_runs.jsonl` 1줄 추가. `cache/`는 안 넣는다.
- PR 본문: 실패 태그 표(`answer_failures.py` 출력) + 새 run과 옛 관문 run·나열 run의 `metrics` 나란히(G0~G5). 어느 모양이 나은지 판단은 쓰지 않는다. 사용자가 [6]-1 규칙으로 고른다.
