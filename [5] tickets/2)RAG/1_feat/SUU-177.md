# SUU-177 feat(rag): answer_question이 단계마다 진행 이벤트를 알린다

## 목표
`answer_question`에 `on_event` 콜백을 넣어 search → found(조문 목록) → answer 세 번 알린다. 반환값은 그대로.

## 건드릴 파일
- 고침: `[3] backend/app/answer.py` — `answer_question(..., on_event=None)` 인자 추가, 세 곳에서 호출
- 테스트(이미 있음, 수정 금지): `[3] backend/tests/test_answer_events.py`

## 안 하는 것
- `app/main.py`, `/ask` 엔드포인트 — SUU-178
- 프론트 — SUU-179
- `ecfr_search`, `ecfr_answer` 등 `[6] rag` 코드
- 반환 dict 모양·토큰 계산·`ms` 변경

## 완료 기준 ↔ 테스트
| 완료 기준 | 테스트 함수 |
|---|---|
| `on_event` 없이 부르면 결과가 지금과 같다 | `test_without_on_event_result_is_unchanged` |
| `on_event`를 주면 search → found(sections 10개) → answer 순서로 3번 불린다 | `test_on_event_gets_search_found_answer_in_order` |
| 기존 테스트 통과 | `test_answer.py`, `test_main.py` |

## Codex 메모
- 시그니처: `on_event: Callable[[dict], None] | None = None` (keyword-only, 기존 `chat` 뒤). `Callable`은 이미 import 돼 있다.
- 호출 위치 세 곳:
  1. `search_sections(...)` **직전**: `{"stage": "search"}`
  2. `search_sections` 끝나고 `build_answer_request` **직전**: `{"stage": "found", "sections": [...]}` — sections는 반환 dict의 `sections`와 **같은 리스트** (`[{"section_key": s["section_key"], "subpart": s["subpart"]} for s in found]`). 한 번 만들어 변수에 두고 이벤트와 반환 둘 다에 쓰면 된다.
  3. `chat(request)` **직전**: `{"stage": "answer"}`
- `on_event`가 None이면 아무것도 안 한다. 작은 헬퍼 `def emit(e): on_event and on_event(e)` 정도면 충분. 예외 처리·try 불필요.
- 테스트는 `tests.test_answer`에서 fixture를 import한다 → `[3] backend/tests/__init__.py`가 없으면 pytest rootdir conftest로 이미 잡히는지 확인: `python -m pytest --ignore=tmp -q -k answer_events` 가 지금 "1 failed, 1 passed"면 import는 된다는 뜻.
