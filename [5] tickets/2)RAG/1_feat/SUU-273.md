## Codex 메모

### 답 모양 v2 (계획 문서 [4]-3)
```
{"candidates": [{"subpart": "PPPP", "title": "...",
                 "gates": [{"type": "affected_source", "question": "...", "test": "...",
                            "citations": ["40 CFR 63.4581"], "quote": "20~40단어 원문 발췌"}],
                 "missing": ["..."]}],
 "checklist": [{"item": "...", "gate": "affected_source"}]}
```
`type`은 `source_category · affected_source · major_or_area · threshold · exemption · compliance_date` 중 하나지만 채점기는 값을 검사하지 않는다(어떤 문자열이든 관문 `type`으로 본다).

### 함수 시그니처 (테스트가 부르는 이름 그대로)
```python
def score_quote_match(answer: dict, section_texts: dict[str, str]) -> tuple[float, list[str]]
def score_checklist_link(answer: dict) -> float
def score_answer_v2(answer: dict, case: dict, section_texts: dict[str, str]) -> dict
def aggregate_v2(rows: list[dict]) -> dict
```
- `section_texts`: `{section key: 조문 전문}`. 키는 `ecfr_eval.citation_section_key`가 만드는 `"section-63.4581"` 꼴. `run_answer.py`의 `fetch_texts`가 이미 이 모양으로 돌려준다(1단계에서 연결).

### G1 `score_quote_match`
- 관문마다: `quote`와 그 관문의 `citations`가 가리키는 조문 전문(여러 개면 이어 붙여도 됨)을 **둘 다** 정규화해 부분 문자열 검사. 정규화 = 소문자 + 연속 공백을 한 칸으로(`" ".join(text.split()).lower()`). 그 외 기호는 건드리지 않는다.
- 인용 조문이 `section_texts`에 없으면(넘겨준 조문 밖) 대조할 원문이 없으니 불일치. `quote`가 빈 문자열이어도 불일치. `citation_section_key`가 `ValueError`를 내는 인용(표·부록)은 건너뛴다.
- 비율 = 일치 관문 수 / 전체 관문 수. 관문 0개면 `(0.0, [])`. 불일치 목록은 `f"{subpart}/{type}"`, 답에 나온 순서.

### G4 `score_checklist_link`
- 관문 `type` 집합 = 모든 후보의 `gates[].type`. `checklist[].gate`가 그 집합에 있으면 연결됨. 비율 = 연결 / 체크리스트 길이. 체크리스트 비면 0.0.

### `score_answer_v2` 반환 키 (순서 무관, 값은 위 테스트 그대로)
`case_id, scorer_version("v2"), g0_grounded, g0_outside, g1_quote, g1_mismatched, g2_subpart, g3_citation_recall, g4_checklist, failed`
- `g0_grounded, g0_outside` = `score_citation_grounded(answer, list(section_texts))`
- `g2_subpart` = `score_subpart`, `g3_citation_recall` = `score_citation_recall` (기존 함수 재사용)
- `failed` = `g0_grounded < 1 or g2_subpart == 0`. G1·G4는 지표로만 깎인다.
- `cost_usd`·`latency_s`는 채점기가 만들지 않는다. 러너가 row에 붙인다(1단계). `aggregate_v2`는 있으면 쓰고 없으면 그 키를 0.0으로.

### `_answer_sections` 확장
- 지금은 `candidates[*].criteria[*].citations`만 본다. `candidates[*].gates[*].citations`도 같이 모은다(둘 다 있으면 둘 다). 그래야 v1 함수 `score_citation_recall`·`score_citation_grounded`가 두 모양을 다 잰다. v1 테스트(`test_ecfr_answer_score.py`)는 그대로 통과해야 한다.

### `aggregate_v2`
- 반환 `{"scorer_version": "v2", "n", "g0_grounded", "g1_quote", "g2_subpart", "g3_citation_recall", "g4_checklist", "g5_cost_usd", "g5_latency_s", "failed"}`. 평균은 산술 평균, `g5_latency_s`만 **중앙값**(`statistics.median`). `failed` = `row["failed"]`가 True인 case_id, 입력 순서. 빈 입력이면 `n: 0`, 나머지 0.0, `failed: []`.

### 선별셋 `make_subset.py` → `rag_eval_subset.json`
- 입력 `[6] rag/eval/rag_eval_case_v2.jsonl` 102건(ADI 69 · Dashboard 33).
- 정답 Subpart 조합 = `set(gold_subparts) - {"A"}` (비면 `{"A"}`). 전체에 76가지 조합, 같은 조합 최대 3건.
- 고르는 법(결정적, `random.Random(273)`): 출처별로 나눠 ADI 35 · Dashboard 16을 뽑되, 같은 조합이 2건을 넘지 않게. 방법 예: 조합별로 케이스를 묶고, 조합을 셔플한 뒤 라운드로빈으로 하나씩 뽑아 목표 수까지 채운다(첫 바퀴에 조합마다 1건 → 두 번째 바퀴에 2건째). 서로 다른 조합 40개 이상이 되는지 테스트가 확인한다.
- 눈 검사 10건: 선별셋 안에서 정답 조합이 서로 다른 것 10건, ADI·Dashboard 둘 다 들어가게(예: ADI 7 · Dashboard 3). 같은 seed로 결정적으로.
- JSON은 `{"subset": [...], "eye": [...]}`, `indent=2`, `ensure_ascii=False`. **한 번 만들어 커밋한 뒤에는 바꾸지 않는다.** 스크립트는 재현용으로만 둔다.

### `eye_check_template.md`
- 계획 문서 [5]-3 그대로. 맨 위에 쓰는 법 3줄(후보 하나에 약 20분, 관문마다 "뒷받침됨 / 안 됨", 케이스마다 "EPA 이유 있음 / 없음", 질문이 공장이 "답할 수 있는 꼴"인가), 그 아래 눈 검사 10건 case_id마다 빈 칸 표(`뒷받침` · `EPA 이유` · `답할 수 있는` 열). 후보 이름과 날짜를 적는 칸 하나.
