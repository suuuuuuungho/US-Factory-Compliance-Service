## Codex 메모

### `ecfr_answer.py` — `verify_answer(answer, given, texts) -> dict`
- 입력을 바꾸지 않는다(`copy.deepcopy` 뒤 작업). 관문(gates) 모양 답만 대상. `criteria` 모양이 들어오면 그대로 돌려준다.
- 관문 하나를 지우는 조건(채점기와 같은 판정):
  - G0: `citations` 중 `citation_section_key`(`ecfr_eval`)로 풀리는 것이 하나라도 `given` 밖. 풀리지 않는 인용(부록·표, `ValueError`)은 채점기 `_answer_sections`처럼 무시.
  - G1: `" ".join(quote.split()).lower()`가 인용 조문들의 원문(같은 정규화, `" ".join`으로 이어 붙임) 안에 없다. `ecfr_answer_score.score_quote_match`의 판정 그대로. 원문이 `texts`에 없는 인용은 소스에 안 들어간다.
- 지운 관문은 `cand["missing"]` 끝에 `f"{gate['type']}: {gate['question']}"`로 붙인다. `missing`이 없으면 만든다.
- 남은 관문 type 집합(모든 후보 합침)에 없는 `gate`를 가진 `checklist` 항목은 지운다. 채점기 `score_checklist_link`가 type 집합으로 보므로 같은 기준.
- 후보의 관문이 전부 지워져도 후보는 남긴다(`gates: []`). G2는 후보 subpart로 잰다.
- 가장 쉬운 구현: `score_citation_grounded`/`score_quote_match`를 관문 하나짜리 임시 답 `{"candidates": [{"subpart": ..., "gates": [gate]}]}`에 각각 불러 outside/mismatched가 비었는지 본다. 채점기 파일은 고치지 않는다.

### `run_answer.py`
- `default_run_id(shape, model, *, subset, max_completion_tokens, verified=False, day=None)`: 기존 문자열 뒤에 `verified`면 `"_verified"`. 순서는 `_subset51` → `_out20k` → `_verified`.
- `answer_run_record(..., verified: bool = False)` → 기록 dict 끝에 `"verified"` 키. 옛 줄에는 이 키가 없다. 없으면 False로 본다. 옛 줄에 채워 넣지 않는다.
- `argparse`: `--verify`(store_true), `--replay-from RUN_ID`. `main()`에서 `args.run_id`가 없으면 `default_run_id(..., verified=args.verify)`.
- `--replay-from`: `saved`를 `RESULTS / f"{args.replay_from}.jsonl"`에서 읽고, `--replay`와 같은 재사용 경로(raw_answer·tokens·cost_usd·latency_s 복사)로 간다. 선택된 케이스마다 저장 행이 있어야 한다(없으면 `ValueError`). 자기 run_id 파일이 아니라 다른 파일에서 읽는 것만 다르다.
- `--verify`: `one()`에서 `parse_answer` 뒤, `score_line` 앞에 `answer = verify_answer(answer, given, {k: texts[k] for k in given if k in texts})`. `answer`가 None(파싱 실패)이면 그대로 None. `out["answer"]`에는 검증한 답을 넣는다. `raw_answer`는 원문 그대로.
- `--retry-empty`는 `--verify`와 같이 써도 된다(재호출 뒤 검증). 이번엔 쓸 일이 없다.

### `answer_pass_line.py`
- v1(`DEFAULT_RUN`, `PASS_LINE`, `is_default_run`, `latest_default_run`, `check_pass_line`)은 한 글자도 안 바꾼다.
- 추가:
  ```python
  TIE_BAND_FULL = 0.03  # 계획 [5]-4: 전체셋 102건 동점 폭
  DEFAULT_RUN_V2 = {"scorer_version": "v2", "shape": "gates", "top_n": 10, "always_sections": [], "subset": False,
                    "answer_model": "gpt-5-mini", "max_completion_tokens": 20000, "verified": True}
  PASS_LINE_V2 = {"g0_grounded": ?, "g1_quote": ?, "g2_subpart": ?, "g3_citation_recall": ?, "g4_checklist": ?, "g5_cost_usd": ?}
  ```
  `?`는 102건 검증 run이 끝난 뒤 채운다: G0~G4 = `round(metrics[k] - 0.03, 3)`, `g5_cost_usd = round(metrics["g5_cost_usd"] * 1.1, 4)`.
- `is_default_run_v2(run)`: `DEFAULT_RUN_V2` 키 전부 같아야 한다. `verified`·`always_sections` 키가 없으면 각각 False·[]로 본다.
- `latest_default_run_v2(runs)`: `run_at` 최대. 없으면 None.
- `check_pass_line_v2(run) -> {k: (round(value, 3), line, ok)}`: G0~G4는 `value >= line`, `g5_cost_usd`는 `value <= line`.
- `main()`: v1 검사 뒤에 v2 검사도 출력. v2 기준 run이 없으면 그 줄만 알리고 v1 결과로 exit code. 둘 다 있으면 둘 다 통과해야 0.

- 3번 끝나면 `PASS_LINE_V2` 숫자를 채우고 `python -m pytest -q`로 `test_answer_pass_line.py` 초록 확인.

### 계획 문서 `[1] docs/3) rag/2_rag 구축 계획.md`
- [7] 선택 근거표. 줄 번호 `n)`와 앞머리(단계 이름)는 그대로 두고 괄호만 채운다. 빈 괄호 `( )`가 1·5·7·8번에 남으면 테스트가 빨강.
  - 1) `… → 고른 것: 관문 → 이유: G0 0.993 vs 0.961(차이 0.032, 동점 폭 0.04 안) → G1 나열 없음 vs 관문 0.869로 관문 승. 눈 10건: 나열 8/10·관문 5/10 전부 뒷받침, EPA 이유 9/10·8/10`. run: `2026-09-26_answer_criteria_gpt-5-mini_subset51` vs `2026-09-26_answer_gates_gpt-5-mini_subset51_out20k`(1차 관문 run은 빈 답 10건이라 상한 20,000으로 재실행, SUU-277)
  - 2) `건너뜀 → 이유: 질문당 $0.023이라 아낄 돈이 없고 약한 G3(0.62)를 깎을 위험만 있다`
  - 3) `건너뜀 → 이유: 상위 10개에 없는 정답 조문 30개 중 22개는 Subpart 자체가 없어(검색 문제) 덧붙여도 못 준다. 건질 수 있는 건 최대 8개(정의 조문 5)라 동점 폭 안. 입력 토큰 +34% 이상 (SUU-276 취소)`
  - 4) `건너뜀 → 이유: 코드가 가장 크고 효과가 불확실. 시간 부족`
  - 5) 51건 대조군 vs 51건 검증 run의 G0/G1/G3 숫자 → 고른 것 → 이유(규칙대로)
  - 6) `건너뜀 → 이유: 서비스 연결 뒤에 스트리밍과 함께 본다`
  - 7) 51건 검증 run 점수 vs 102건 검증 run 점수(G0~G4), 차이가 0.03 안인지
  - 8) `모양 관문 + 조문 10개 + 덧붙임 없음 + 생성 한 번 + 검증문 있음 + 모델 gpt-5-mini → 점수 (102건 검증 run G0~G4) → 합격선 (PASS_LINE_V2)`
