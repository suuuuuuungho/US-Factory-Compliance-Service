## Codex 메모
- **`search_sections(question, *, embed, chunks, rerank=None, top_k=5, chunk_top_k=300)`**. `rerank`가 있으면: `ranked = rank_chunks_by_similarity(...)` → `scores = rerank(question, ranked)` (길이 같음, 입력 순서와 같은 순서) → 각 청크의 `score`를 리랭커 점수로 바꾼 목록을 `rank_sections(..., k_max=top_k)`에 넘긴다. `rank_sections`가 `(-score, chunk_key)`로 정렬하므로 따로 정렬 안 해도 된다. 청크 dict를 그대로 바꾸지 말고 `{**c, "score": s}`로 새로 만든다.
- **`build_rerank_request(question, chunks) -> dict`**: `{"query": question, "texts": [...]}`. 텍스트는 `ecfr_embed.build_embedding_request`와 같은 규칙(`context_text + "\n\n" + chunk_text`, context가 None/빈 문자열이면 chunk_text만). `model`은 넣지 않는다(호출 함수가 붙임, `call_kanon2_api`와 같은 방식).
- **`call_isaacus_rerank_api(request) -> {"scores": list[float], "input_tokens": int}`** (`ecfr_chunk_index.py`, `call_kanon2_api` 옆): `POST https://api.isaacus.com/v1/rerankings`, 헤더 `Authorization: Bearer {ISAACUS_API_KEY}`, 바디 `{"model": "kanon-2-reranker", **request}`, timeout 120. 응답 `{"results": [{"index": int, "score": float}, ...], "usage": {"input_tokens": int}}` — results는 점수순이므로 **`index`로 입력 순서에 되돌려** `scores[index] = score` 로 채운다. 문서: https://isaacus.com/docs/capabilities/reranking
- **`run_eval.py`**: `argparse`로 `--config` (`contextual` 기본 | `rerank`). `rerank`면 (1) `fetch_chunks`의 select에 `context_text,chunk_text` 추가, (2) `search_sections(..., rerank=rerank, chunk_top_k=150)` — `rerank`는 `build_rerank_request` → `call_isaacus_rerank_api` 를 부르고 `input_tokens`를 합산하는 클로저, (3) run_id `f"{today}_{config}_v1"`, run 기록의 `config` 값과 `cost_usd = {"per_query": total/32, "total": input_tokens_sum * 0.35 / 1e6}` 채움, (4) `latency_ms.search`에 리랭크 호출 시간이 포함되도록 그대로 둔다(`search_sections` 한 번을 재므로 자동). `contextual`이면 지금과 완전히 같은 동작·출력.
- `run_eval.py`의 `notes` 문자열은 config에 맞게 짧게 바꿔도 된다. 결과 필드 이름은 계획 [8] 그대로.
- 표준 라이브러리 + 이미 쓰는 `requests`만.
