# SUU-275 feat(rag): 51건 나열 vs 관문 답 run 2개 기록

## 목표
`run_answer.py`를 심판 없이 채점기 v2·선별셋 51건·상위 10 조문·답 모양 인자로 바꾸고, 나열(`criteria`)·관문(`gates`) run을 하나씩 실제로 돌려 `answer_runs.jsonl`에 남긴다. 계획 문서 `[1] docs/3) rag/2_rag 구축 계획.md` [6]-3 1단계. 비용 ≈ $2.

## 건드릴 파일
- 고침: `[6] rag/eval/run_answer.py` — `--shape`, `--subset`, 기본 `--top-n 10`, 심판 제거, 채점기 v2, row에 비용·지연·토큰, run 기록 v2, 같은 run_id 줄 덮어쓰기
- 고침: `[6] rag/eval/answer_failures.py` — `classify_v2`·`TAGS_V2`, `summarize(..., tags=)`, `main`이 v2 행이면 v2 태그로
- 만듦(실행 결과): `[6] rag/eval/results/<run_id>.jsonl` 2개, `[6] rag/eval/answer_runs.jsonl` 2줄 추가
- 테스트(이미 있음, 수정 금지): `[6] rag/tests/test_run_answer.py`, `[6] rag/tests/test_answer_failures.py`

## 안 하는 것
- 프롬프트·파서(`ecfr_answer.py`), 채점기(`ecfr_answer_score.py`) 수정
- 조문 개수 비교(2단계), Subpart A 덧붙임 비교(3단계), 검증문(5단계). `--always-a`는 코드에 남기되 이번 run에서는 안 쓴다
- `answer_pass_line.py`·`test_answer_pass_line.py` 수정. 옛 합격선은 옛 run(judge_model 있음)을 계속 본다. v2 합격선은 7단계
- 눈 검사·계획 문서 [7] 근거표 채우기(사람이 run 뒤에 함), 계획 문서 수정
- 검색 다시 돌리기, 프론트, `rag_eval_subset.json` 수정

## Codex 메모

### 1. `run_answer.py` 바꾸는 것
지금: 102건 전체 · `TOP_N = 5` · 답 → gpt-5-mini 심판 → v1 채점(`score_subpart/score_citation_recall/score_citation_grounded` + `aggregate`). 바꿀 것:

- **상수·인자**
  - `TOP_N = 10`. `SUBSET_PATH = HERE / "rag_eval_subset.json"`.
  - `--shape {criteria,gates}` 기본 `criteria`. `build_answer_request(..., shape=args.shape)`·`parse_answer(raw, given, shape=args.shape)` (SUU-274).
  - `--subset`: `json.load(SUBSET_PATH)["subset"]`(51 case_id)에 든 검색 줄만. `select_cases(lines, case_ids | None) -> list[dict]`. `--limit`은 그 뒤에 자른다.
  - `--judge-model` 인자·`build_judge_request`·`parse_judge`·`aggregate`(v1) import 전부 뺀다. `ecfr_answer_score`에서 `score_answer_v2`·`aggregate_v2`만 쓴다.
  - `--run-id` 기본값: `f"{오늘}_answer_{shape}_{model}" + ("_subset51" if subset else "")`. `argparse`에서 `parse_known_args` 두 번 쓰는 지금 방식은 shape·subset도 봐야 하니 `args.run_id is None`이면 `parse_args()` 뒤에 채우는 쪽이 간단하다.
- **케이스 한 줄** `one(line)`:
  - 호출 전후 `time.perf_counter()` 차이 = `latency_s`. `call_openai_chat`이 돌려주는 `prompt_tokens`·`completion_tokens`로 케이스 비용 = `p/1e6*pin + c/1e6*pout` (`PRICE_PER_M[model]`, 없으면 0).
  - `--replay`·`--retry-empty` 재사용 때는 저장 row의 `raw_answer`·`prompt_tokens`·`completion_tokens`·`cost_usd`·`latency_s`를 그대로 쓴다(새 호출 없음). 옛 결과 파일(v1, 이 키 없음)은 replay 대상이 아니다. `judge_text`는 더 이상 읽지도 쓰지도 않는다.
  - `score_line(case, answer, *, given, texts, issues, tokens, cost_usd, latency_s) -> dict`:
    - `answer`가 있으면 `score_answer_v2(answer, case, {k: texts[k] for k in given if k in texts})`의 키 전부(`case_id, scorer_version, g0_grounded, g0_outside, g1_quote, g1_mismatched, g2_subpart, g3_citation_recall, g4_checklist, failed`).
    - `answer`가 `None`이면 같은 키를 0.0 / `[]` / `False`→`failed: True`로 채운다(`g2_subpart`는 `0`).
    - 거기에 `answer, given, issues, cost_usd, latency_s, prompt_tokens, completion_tokens`. 호출부에서 `raw_answer`도 붙인다(지금처럼).
    - `texts`: `fetch_texts`가 돌려주는 `{section_key: 전문}`. `--replay`면 지금은 `texts = {}`인데, G1(발췌 대조)에 전문이 필요하니 **replay에서도 `fetch_texts`를 부른다**(캐시 `cache/section_texts.json`에 다 있으면 Supabase를 안 부른다).
  - 진행 출력은 `g0 g1 g2 g3 g4`와 `failed`로.
- **run 기록** `answer_run_record(run_id, outs, *, search_run_id, model, shape, top_n, subset, cost, always=(), tokens=None) -> dict`:
  ```
  run_id, run_at(UTC …Z), search_run_id, eval_set_version "v2", subset(bool), n_cases, top_n, always_sections(list),
  answer_model, shape, scorer_version "v2", tokens{prompt, completion, prompt_per_case}, metrics = aggregate_v2(outs),
  cost_usd{per_query, total}
  ```
  `judge_model` 키를 **넣지 않는다**. `answer_pass_line.is_default_run`이 `judge_model == "gpt-5-mini"`를 요구하므로 v2 줄은 자동으로 제외되고 옛 합격선 검사(`test_latest_default_run_in_answer_runs_jsonl_passes`)가 계속 옛 run을 본다. 7단계에서 v2 합격선을 따로 만든다.
- **쓰기** `write_run_record(path, rec)`: 파일의 줄 중 `run_id`가 같은 줄이 있으면 그 자리에서 바꾸고, 없으면 끝에 붙인다. `--limit`이면 지금처럼 안 쓴다.
- 안 바꾸는 것: `join_section_text`, `top_sections`, `fetch_texts`, `ALWAYS_SECTIONS`, `SEARCH_RUN_ID`, `--workers`, `--always-a`.

### 2. `answer_failures.py`
- `TAGS_V2 = ("format", "fabricated", "quote_mismatch", "search", "answer")`. 계획 [5]-5의 자동 태그. `format`(답 없음)을 맨 앞에 둔 이유: 파싱이 안 되면 다른 점수가 아예 없다. `unsupported`·`structure`는 눈 검사 태그라 여기 없다. `checklist`는 G4 지표로만 보고 태그 안 한다.
- `classify_v2(out, case) -> str | None`:
  1. `out["answer"] is None` → `format`
  2. `out["g0_outside"]` 비어 있지 않음 → `fabricated`
  3. `out["g1_mismatched"]` 비어 있지 않음 → `quote_mismatch`
  4. `out["g2_subpart"] == 0`이고 정답 조문(`citation_section_key(gold_citations)`)이 `out["given"]`에 하나도 없음 → `search`
  5. `out["g2_subpart"] == 0` → `answer`
  6. 그 외 → `None`
- `summarize(outs, classify_fn, tags=TAGS)`: 지금 함수에 `tags` 인자만 추가.
- `main`: 결과 파일 첫 행에 `scorer_version == "v2"`면 `classify_v2`·`TAGS_V2`, 아니면 지금처럼. 케이스별 한 줄 출력에서 `judge` 대신 `g1_quote`·`g4_checklist`.
- v1 `classify`·`TAGS`·그 테스트 6개는 그대로.

### 3. 실제로 돌리기 (Codex가 한다, 총 ≈ $2)
```
python "[6] rag/eval/run_answer.py" --shape criteria --subset
python "[6] rag/eval/run_answer.py" --shape gates --subset
python "[6] rag/eval/answer_failures.py" --run-id <criteria run_id>
python "[6] rag/eval/answer_failures.py" --run-id <gates run_id>
```
- `.env`에 `OPENAI_API_KEY`·`SUPABASE_URL`·`SUPABASE_SECRET_KEY`. `load_env()`가 읽는다. 조문 전문은 `cache/section_texts.json`에 대부분 있다(상위 10은 SUU-152에서 이미 받아둠).
- 빈 답(파싱 실패)이 있으면 `--retry-empty`로 한 번 더. 그래도 비면 그대로 둔다(`format` 태그).
- 커밋에 넣는 것: 코드 2개, `results/<run_id>.jsonl` 2개, `answer_runs.jsonl`(2줄 추가). `cache/`는 커밋하지 않는다(지금 `.gitignore` 상태 그대로).
- 실패 태그 표 2개는 PR 본문에 붙인다(파일에 쓰지 않는다). 점수 비교·고르기는 사람이 계획 [6]-1 규칙(G0 → G1 → … 동점 폭 0.04)으로 하고 [7]에 적는다. Codex는 고르지 않는다.

### 4. 확인
- `python -m pytest -q -k "run_answer or answer_failures or answer_pass_line"` → `test_run_answer.py` 18개, `test_answer_failures.py` 14개, `test_answer_pass_line.py` 4개 초록. `test_saved_criteria_and_gates_runs_share_the_same_51_cases`는 실제 run 2개를 커밋해야 초록이 된다.
- `test_every_saved_answer_run_has_tokens`: 새 줄도 토큰 > 0 이어야 한다. `--replay`로 다시 쓸 때 저장 row의 토큰을 합쳐 넣어야 0이 안 된다.
