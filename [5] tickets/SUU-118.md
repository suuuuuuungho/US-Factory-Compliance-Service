# SUU-118 fix(db): ECHO 파서가 Pipeline 연결용 집합을 한 번만 만든다

## 목표
`parse_release`가 Pipeline 행마다 `activities | violations`를 새로 합치지 않고, Pipeline 파일 시작 전에 한 번 만든 집합을 모든 행에 넘긴다.

## 건드릴 파일
- 고칠 것: `[2] db/pipeline/3_ECHO/echo_parse.py` (161행 근처 한 곳)
- 이미 있음 (수정 금지): `[2] db/tests/3_ECHO/test_echo_parse.py`

## 안 하는 것
- 다른 모듈, 출력 형식(jsonl·report 키), 기존 동작 변경
- 메모리 줄이기 등 다른 최적화
- `tests/` 수정

## 완료 기준 ↔ 테스트
| 완료 기준 | 테스트 함수 |
|---|---|
| `pipeline_row`가 모든 Pipeline 행에서 **같은** known 객체를 받고, 내용은 activity 키 전부 ∪ `("violation", id)` 전부와 같다 | `test_pipeline_rows_share_one_known_set_built_once` |
| 기존 3개 테스트 그대로 통과 | `test_fake_release_*`, `test_report_counts_*`, `test_missing_required_column_*` |

## Codex 메모
- 원인: `echo_parse.py:161` `pipeline_row(row, number, activities | violations)` — 실제 데이터에서 집합 550만 개를 67,122번 복사해 초당 13행. 앞 10개 파일은 5분, Pipeline만 1시간 반.
- 고치는 법: 파일 순서가 고정이라(ICIS-Air 10개 → Pipeline) Pipeline 차례엔 `activities`·`violations`가 더 안 늘어난다. `for member in ...` 루프 안에서 `member`가 Pipeline일 때 한 번 `known = activities | violations`를 만들어 행마다 그걸 넘기면 된다. 함수 시그니처·반환값 그대로.
- 테스트는 `echo_parse.pipeline_row`를 monkeypatch해 넘어온 객체가 `is`로 같은지 본다. 그러니 `pipeline_row`는 모듈 전역 이름으로 계속 불러야 한다 (지역 변수에 미리 담아두면 monkeypatch가 안 먹는다).
