## Codex 메모
- 색 토큰은 이미 `globals.css` `@theme`에 있음: `--color-gradient-violet/magenta/orange/coral` → Tailwind 클래스 `border-gradient-violet`, `bg-gradient-violet` 등이 바로 동작한다.
- 테스트는 `classList.contains`로 **정확한 클래스 이름**을 본다. 아래 이름 그대로 써야 한다.
- 후보 카드: `result.answer.candidates.map((c) => ...)` 에 index를 받아 순환한다.
  ```tsx
  const STRIPES = ["border-gradient-violet", "border-gradient-magenta", "border-gradient-orange", "border-gradient-coral"];
  // map((c, i) => ...)
  className={`rounded-lg border border-hairline border-l-4 bg-surface-1 p-5 ${STRIPES[i % STRIPES.length]}`}
  ```
  기존 클래스(`rounded-lg border border-hairline bg-surface-1 p-5`)는 유지해야 SUU-172 테스트가 계속 초록이다. `border-l-4`가 왼쪽 두께, `border-gradient-*`가 색을 정한다 — Tailwind에서 `border-hairline`(전체 색) 뒤에 `border-gradient-violet`을 쓰면 전체 테두리 색이 바뀌므로, 왼쪽만 색을 주려면 `border-l-gradient-violet` 형태가 필요하지만 **테스트는 `border-gradient-violet` 클래스명을 요구**한다. 그래서 `border-gradient-violet`을 그대로 쓰고, 나머지 세 변은 `border-t-hairline border-r-hairline border-b-hairline`으로 다시 덮는다 (또는 4변 모두 색 띠 색이어도 무방 — 디자인상 허용).
- Checklist 카드: `className="rounded-xl bg-gradient-violet p-5 text-ink"` (DESIGN.md gradient-spotlight-card: 배경 violet, 글자 ink, rounded xl). `border`는 뺀다.
- 색 띠 순서: violet → magenta → orange → coral → 다시 violet.
- 확인: `[4]frontend`에서 `npm test` 20개 전부 초록, `npm run build` 성공.
