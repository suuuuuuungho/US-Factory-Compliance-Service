# SUU-229 feat(frontend): Federal Register에 빨강·초록 diff 뷰를 그린다

## 목표
`/federal-register`가 `/fr-diff.json`을 읽어 규칙 목록을 그리고, 규칙을 누르면 바뀐 섹션의 바뀐 문단만 GitHub diff처럼 보인다.

## 건드릴 파일
- 고칠 것 `[4]frontend/src/app/federal-register/page.tsx` — `"use client"`. mount 시 `fetch("/fr-diff.json")`. 목록 + 누르면 펼치기
- 만들 것 `[4]frontend/src/components/FrDiff.tsx` — 문서 하나의 섹션·문단 diff 렌더 (page가 커지면 분리, 작으면 page 안에 둬도 됨)
- 고칠 것 `[4]frontend/package.json` — `diff` 패키지 추가 (`npm i diff`, `@types/diff`는 v8부터 자체 타입 포함)

## 안 하는 것

- `[4]frontend/tests/**` 수정 (Codex 금지)

## 완료 기준 ↔ 테스트
테스트 파일: `[4]frontend/tests/fr_diff_view.test.tsx` (`[4]frontend`에서 `npm test`)

| 완료 기준 | 테스트 함수 |
|---|---|
| 목록에 제목·게재일·시행일·`+N −M` 요약 | `목록: 제목·게재일·시행일·+N −M 요약이 보인다` |
| removed 문단 `.diff-removed`, added 문단 `.diff-added` | `removed 문단에 diff-removed, added 문단에 diff-added 클래스가 붙는다` |
| changed 문단은 바뀐 단어만 `<mark>` | `changed 문단은 바뀐 단어만 <mark>로 감싼다` |
| 안 바뀐 섹션은 DOM에 없다 | `안 바뀐 섹션(63.461)은 DOM에 없고 바뀐 섹션(63.460)만 있다` |
| reason 있는 문서는 "변경 본문 없음" | `diff 없는 문서는 '변경 본문 없음' 을 보인다` |

## Codex 메모

### JSON 모양 (SUU-228 `fr_diff.py build()` 출력)
```
{ generated_at, since, documents: [ {
    document_key, document_number, title, citation, canonical_url,
    publication_date, effective_date | null,
    amended_sections: ["63.460", ...],
    reason: null | "no_effective_date" | "no_xml" | "no_sectno" | "no_text_change",
    summary: { added, removed, changed },
    sections: [ { section, node_key, before_date, after_date,
                  rows: [ { kind: "equal"|"removed"|"added"|"changed", before, after, is_context } ] } ]
} ] }
```
- `sections`에는 **바뀐 섹션만** 들어 있다. `amended_sections`는 그리지 않는다 (63.461 이 DOM에 없어야 함)
- `rows`의 `equal`은 앞뒤 맥락 1줄. 회색(`text-ink-muted`)으로 보여도 되고 안 보여도 된다. 테스트는 안 본다
- `reason`이 있으면(=`sections` 비어 있음) 펼쳤을 때 `변경 본문 없음` 글자를 보인다

### 그리기 규칙
- 목록 항목은 `<button>`이고 접근 이름에 `title`이 들어가야 한다 (`findByRole("button", { name: /제목/ })`)
- 요약은 `+{added} −{removed}` 한 덩어리 텍스트. 마이너스는 `−`(U+2212)
- removed 문단: 감싸는 요소에 클래스 `diff-removed`, 글자는 `before`
- added 문단: 클래스 `diff-added`, 글자는 `after`
- changed 문단: 클래스 `diff-changed`, `diffWords(before, after)` 결과를 순서대로 그린다. `removed` 조각과 `added` 조각은 `<mark>`, 나머지는 그냥 텍스트. 테스트 기대값: `["A.", "B."]` (removed 먼저, added 다음 — diffWords 기본 순서)
- `import { diffWords } from "diff"`

### 색 (DESIGN.md 토큰만)
- 빨강 토큰이 없다. removed·removed mark → `gradient-coral`(#ff5577). added·added mark → `semantic-success`(#22c55e)
- Tailwind v4는 `text-[var(--color-gradient-coral)]` 또는 globals.css `@theme`에 이미 있으면 `text-gradient-coral` / `bg-…/15` 같은 식으로 쓴다. 기존 페이지(`applicability/page.tsx`)의 클래스 쓰는 법을 따른다
- 폰트 추가 없음. 본문 SF Pro(기본)

### 기타
- `fetch`는 상대경로 `/fr-diff.json` 으로 부른다 (테스트가 `url.endsWith("/fr-diff.json")`로 본다)
- 첫 번째 테스트는 fetch가 `headers` 없는 Response를 준다. `res.json()`만 쓰면 된다
- 실제 `public/fr-diff.json`은 SUU-228 PR이 넣는다. 그 전엔 로컬 dev에서 404 → 빈 목록 + "불러오지 못했습니다" 정도로만 처리. 테스트는 이 경우를 보지 않는다
