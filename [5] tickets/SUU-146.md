### 조문 단위 비교
- 인용 문자열 → section key는 **기존 함수를 그대로 쓴다**: `from ecfr_eval import citation_section_key` (`"40 CFR 63.4481(a)"` → `"section-63.4481"`). 새로 정규식 만들지 말 것.
- 답의 인용 전부 모으기: `answer["candidates"][*]["criteria"][*]["citations"][*]`. 조문 단위로 바꾼 뒤 **set**으로 중복 제거(4481(a)와 4481(b)는 같은 조문 하나).
- Recall 분모 = `set(citation_section_key(c) for c in case["gold_citations"])`.
- 근거율 분모 = 답 인용 set 크기. `outside`는 given에 없는 키를 **답에 나온 순서**로(테스트는 1개라 순서 무관하지만 정렬하지 말고 등장 순).

### 심판 요청
- `JUDGE_MODEL = "gpt-5-mini"`. 반환 dict 모양은 `ecfr_llm_rerank.py`가 OpenAI에 보내는 것과 같은 꼴: `{"model": ..., "messages": [{"role": "system", "content": SYSTEM}, {"role": "user", "content": ...}], "max_completion_tokens": ...}`. gpt-5 계열은 추론 토큰이 출력에 포함되니 `max_completion_tokens`는 2000 정도.
- SYSTEM(영어): 너는 EPA NESHAP 전문가 심판. 공장 질문, 우리 답(후보 Subpart·판정 기준·근거 조문), EPA가 실제 회신에서 적은 판단 근거(notes)를 준다. **"notes의 판단 근거가 답의 criteria에 담겼는가"만** 본다. 최종 결론(적용/미적용)이 답에 없어도 감점하지 않는다. 척도: 2 = notes의 핵심 근거가 criteria에 다 있음 / 1 = 일부만 / 0 = 없거나 반대. `{"score": N, "reason": "..."}` JSON 한 줄로 답하라.
- user: `QUESTION:\n...\n\nOUR ANSWER (JSON):\n<json.dumps(answer, ensure_ascii=False, indent=2)>\n\nEPA NOTES:\n...`

### parse_judge
- 우선 ```json 펜스를 벗기고 `json.loads` 시도 → `score` 키. 실패하면 정규식 `score\D*(-?\d+)`. 둘 다 안 되면 `ValueError`. 값이 {0,1,2} 밖이면 `ValueError`.

### aggregate
- 입력 row 키: `case_id`, `subpart`, `citation_recall`, `citation_grounded`, `judge`. 반환: `{"n", "subpart", "citation_recall", "citation_grounded", "judge", "failed"}`. 평균은 단순 산술 평균.
- `failed` = `subpart == 0` 또는 `judge == 0` 또는 `citation_grounded < 1` 인 case_id, 입력 순서.
