# SUU-160 feat(ci): main에 합쳐지면 Render가 백엔드를 자동 배포한다

## 목표
레포 루트에 `render.yaml`(Blueprint) 하나. Render가 GitHub `main`을 보고 merge마다 `uvicorn app.main:app`을 다시 켠다. `cd.yml` 없음. 사람이 Render 사이트에서 한 번 연결. $0.

## 건드릴 파일
- 만듦: `render.yaml` — 아래 그대로
- 고침: `[1] docs/4) workflow/1_workflow.md` — 5단계 표(백엔드 = Render, "아직 안 정한 것" 행 삭제), 5절 파일 표의 `cd.yml` 행 삭제(대신 `render.yaml`), 7절 "GitHub → Settings" 표에 Render 행, 8절 6번 행에 "백엔드 Render: SUU-160"
- 테스트(이미 있음, 수정 금지): `[3] backend/tests/test_render.py`

## 안 하는 것
- `[3] backend/requirements.txt` 만들기 — 티켓엔 있지만 루트 `requirements.txt`에 fastapi·uvicorn이 이미 있다(SUU-158). Render도 루트에서 `pip install -r requirements.txt`. 파일 두 개면 어긋난다
- `slack.yml` 수정 — 티켓엔 `deployment_status`라 썼지만 Render는 GitHub Deployment 이벤트를 만들지 않는다(문서 확인). Slack 알림은 Render 대시보드 Integrations → Notifications → Connect Slack(무료, 사람이 1분). `deployment_status`는 Vercel이 만드니 SUU-165에서 다룬다
- `.github/workflows/cd.yml`, 유료 플랜, 프론트 배포(SUU-165)
- `app/*` 코드 수정

## Codex 메모

### `render.yaml`
```yaml
# SUU-160: Render Blueprint. main merge마다 자동 배포. 무료 플랜(512MB, 15분 안 쓰면 잠듦 → 첫 요청 30~60초).
# rootDir은 안 쓴다: app.main이 "[2] db/pipeline/5_rag"의 ecfr_* 모듈을 import 하므로 레포 루트에서 PYTHONPATH로 잇는다(pyproject.toml pythonpath와 같은 생각).
services:
  - type: web
    name: us-factory-compliance-api
    runtime: python
    plan: free
    buildCommand: pip install -r requirements.txt
    startCommand: uvicorn app.main:app --host 0.0.0.0 --port $PORT
    healthCheckPath: /health
    envVars:
      - key: PYTHON_VERSION
        value: 3.13.4
      - key: PYTHONPATH
        value: "[3] backend:[2] db/pipeline/5_rag"
      - key: SUPABASE_URL
        sync: false
      - key: SUPABASE_SECRET_KEY
        sync: false
      - key: OPENAI_API_KEY
        sync: false
      - key: ISAACUS_API_KEY
        sync: false
      - key: FRONTEND_ORIGIN
        value: http://localhost:3000
```
- `PYTHON_VERSION`: 로컬은 3.13.14. Render가 받는 3.13.x면 된다(빌드 로그에 없다고 나오면 낮춘다). 테스트는 이 키를 안 본다
- `FRONTEND_ORIGIN`은 SUU-165에서 Vercel 주소로 바꾼다(쉼표로 여러 개, `app/main.py`)
- 테스트는 정규식으로 줄 단위 검사: `- type: web`, `runtime: python`, `plan: free`, 세 명령 줄, `- key: X` 6개, 비밀 4개 바로 다음 줄 `sync: false`, `PYTHONPATH` 다음 줄 `value:`. 위 모양 그대로면 통과

### 메모리
- 색인 80MB + 파이썬 + fastapi ≈ 250~300MB. 512MB 안. 넘치면 Render 로그에 "Out of memory" → pgvector로 옮기는 게 다음 수(rag_eval_plan.md에 적어둠)

### 문서 `1_workflow.md`
- 5단계 표: `하는 일` → "백엔드 → Render(render.yaml), 프론트 → Vercel, DB → Supabase 마이그레이션", `자동으로` → "Render·Vercel Slack 알림(각 대시보드 연동)", `아직 안 정한 것` 행 삭제
- 5절 파일 표: `.github/workflows/cd.yml` 행 → `render.yaml | CD | main merge 시 Render 배포`
- 7절 사람이 한 번 하는 표: `Render | GitHub 레포 연결(Blueprint) + 환경변수 4개 + Slack 연동 | main merge 시 백엔드 자동 배포`
- 8절 6번 행 뒤에 `| 6-b | render.yaml + Render 연결 | /health 200 | SUU-160 |`
