## Codex 메모

테스트가 부르는 것:

```python
def activity_rows(kind: str, row: dict[str, str]) -> tuple[dict, dict]
```

- `kind`는 `inspection` / `stack_test` / `titlev` 셋만. 다른 값은 `ValueError`.
- 실제 헤더 (2026-09-17 ZIP):
  - FCES_PCES 10열: `PGM_SYS_ID, ACTIVITY_ID, STATE_EPA_FLAG, ACTIVITY_TYPE_CODE, ACTIVITY_TYPE_DESC, COMP_MONITOR_TYPE_CODE, COMP_MONITOR_TYPE_DESC, ACTUAL_END_DATE, PROGRAM_CODES, ACTIVITY_PURPOSE_DESC`. 날짜 전부 `MM-DD-YYYY`. 1,819,116행.
  - STACK_TESTS 10열: `PGM_SYS_ID, ACTIVITY_ID, COMP_MONITOR_TYPE_CODE, COMP_MONITOR_TYPE_DESC, STATE_EPA_FLAG, ACTUAL_END_DATE, POLLUTANT_CODES, POLLUTANT_DESCS, AIR_STACK_TEST_STATUS_CODE, AIR_STACK_TEST_STATUS_DESC`. 날짜 `MM/DD/YYYY`, 빈 날짜 4행. 상태 분포: PSS 581k, NA 46k, FAI 21k, PEN 6k, `""` 382, INC 215.
  - TITLEV_CERTS 7열: `PGM_SYS_ID, ACTIVITY_ID, COMP_MONITOR_TYPE_CODE, COMP_MONITOR_TYPE_DESC, STATE_EPA_FLAG, ACTUAL_END_DATE, FACILITY_RPT_DEVIATION_FLAG`. 빈 날짜 29,985행. 플래그 `""` 1.46M / N 750k / Y 371k.
  - 빈 `ACTIVITY_ID`는 세 파일 모두 0건. 없으면 `row["ACTIVITY_ID"]` KeyError 그대로.
- activity 키 순서 (테스트가 dict 통째 `==`):
  `activity_kind, activity_id, type_code, type_desc, lead_flag, monitor_code, monitor_desc, activity_date, raw_date, attributes`
  - `type_code/type_desc` ← `ACTIVITY_TYPE_CODE/DESC` (점검에만 있음; 없으면 `row.get` → None)
  - `lead_flag` ← `STATE_EPA_FLAG`, `monitor_code/monitor_desc` ← `COMP_MONITOR_TYPE_CODE/DESC`
  - `activity_date` ← `parse_date(row["ACTUAL_END_DATE"])`, `raw_date` ← 원문 그대로 (`""`도 `""`)
  - `""` → `None`은 `is_missing`으로 `type_*, lead_flag, monitor_*`와 `attributes` 값 전부에 적용
- `attributes` = 위에서 쓴 열(`PGM_SYS_ID, ACTIVITY_ID, STATE_EPA_FLAG, ACTIVITY_TYPE_*, COMP_MONITOR_TYPE_*, ACTUAL_END_DATE`)을 뺀 **나머지 열 전부**, 키는 원래 열 이름. 파일별로 목록을 하드코딩하지 말고 "쓴 열 집합"을 빼면 된다 (열이 추가돼도 자동 보존).
- activity_facility = `{"activity_kind": kind, "activity_id": row["ACTIVITY_ID"], "pgm_sys_id": row["PGM_SYS_ID"]}`.
- 값 `strip()` 안 함. 표준 라이브러리만, 40줄 안팎. `from echo_values import is_missing, parse_date` (평면 import — `echo_facility.py`·`echo_programs.py`와 같은 방식).
