# SUU-125 feat(db): 검증된 ECHO release를 공개 포인터로 전환한다

## 목표
검사를 통과한 ECHO release를 `published`로 바꾸고 `common_dataset_current(echo, icis_air_national+caa_pipeline)`가 그 release를 가리키게 한다.

## 건드릴 파일
- 만들 것: `[2] db/tests/3_ECHO/test_echo_publish.py` — 테스트만
- **새 모듈 없음.** SUU-67의 `[2] db/pipeline/1_eCFR/ecfr_publish.py::publish_release(release_id, *, client, now=None)`는 dataset·scope_key·source_as_of를 release 행에서 읽어 어떤 데이터셋에도 그대로 쓸 수 있다. 같은 코드를 `echo_publish.py`로 복사하지 않는다 (Simplicity First).

## 안 하는 것
- 검사(SUU-124가 먼저), 이전 release 삭제·보존 정책, 동시 실행 잠금
- `ecfr_publish.py` 수정·이름 변경 (공통 모듈로 옮기는 건 세 번째 데이터셋이 생길 때)

## 완료 기준 ↔ 테스트
| 완료 기준 | 테스트 함수 |
|---|---|
| release status가 published, published_at 채워짐 | `test_publishing_sets_status_published_and_published_at` |
| `common_dataset_current` 포인터가 echo release를 가리키고, 다른 release로 다시 공개해도 이전 release 행이 남는다 | `test_pointer_targets_the_echo_release_and_old_release_row_survives_republish` |

## 메모
- 테스트는 처음부터 초록이다 — 기존 함수가 그대로 맞는다는 증거. SUU-126 `echo_ingest`는 `from ecfr_publish import publish_release`로 쓴다 (`pyproject.toml` pythonpath에 `1_eCFR`·`3_ECHO` 둘 다 있다).
- 공개 후 기존 포인터 행은 `upsert(on_conflict="dataset,scope_key")`로 덮인다. eCFR 포인터(`ecfr`, `40/63`)와 키가 달라 서로 건드리지 않는다.
