# SUU-210 feat(db): FR Part 63 문서를 실제로 수집·파싱·적재한다

## 목표
SUU-206~209가 만든 `fr_collect → fr_parse → fr_ingest`를 진짜로 돌려 DB에서 FR Part 63 문서 1,532건을 조회할 수 있게 하고, 계획 문서의 "미실행" 칸을 실제 수치로 바꾼다.

## 선행 조건 (전부 머지됨)
- SUU-206(수집) · 207(파서) · 208(표) · 209(등록·적재·검사·공개). 실행은 Claude가 한다 (SUU-98·112·127과 같은 실행 티켓).
- `.env`의 `SUPABASE_URL`·`SUPABASE_SECRET_KEY`·`SUPABASE_DB_URL`(Session pooler).

## 건드릴 파일
- 실행: `fr_collect.py --root "[2] db/2) Federal Register" --workers 6` → `fr_parse.py --root … --as-of 2026-09-21` → `run_fr_ingest(root, "2026-09-21", …)` (스크래치 런처, `fr_ingest.__main__`과 같은 일).
- 고칠 것: `[1] docs/2) db/db 구축 계획/2_Federal Register 구축 계획.md` 1-4·1-5·2-3·2-4·2-5·3-3·3-4, 이 파일 하단 "실행 결과".
- `[2] db/pipeline/2_Federal Register/fr_collect.py` — 실행 중 만난 문제라 fix 티켓을 따로 만들지 않고 이 PR에 넣는다 (사용자 결정):
  - 요청을 한 개씩 순서대로 보내면 1,532건 × 3파일이 **약 2시간**(분당 문서 ~12건). 문서 단위로 `ThreadPoolExecutor(workers)` 동시 처리, 결과는 목록 순서대로 합친다. CLI 기본 `--workers 6`, 함수 기본 `workers=1`(기존 테스트 그대로).
  - 테스트: `test_fr_collect.py::test_workers_collect_the_same_files_in_parallel`, `::test_main_defaults_to_several_workers`

## 안 하는 것
- 위 1건 외 코드·테스트 수정, 자동 갱신(Step 4), 조회 뷰, 보완 후보(2차) 수집

## 완료 기준 ↔ 확인 방법
| 완료 기준 | 확인 방법 |

| 목록 행 수 = API 총 건수, 파싱 성공 + held = 수집 수 | `fr_collect` 요약(`count`·`documents`) + `quality_report.json`(`succeeded`·`held`) |
