## Codex 메모

테스트가 부르는 것:

```python
class ParseError(ValueError): ...
def parse_release(root: Path, as_of: date, code_map_version: str) -> dict   # report
```

### 입력
- `root/raw/{as_of}/manifest.json` — 리스트. 각 항목에서 `name`(`ICIS-AIR_downloads.zip` / `pipeline_caa_downloads.zip`), `path`(root 기준 상대), `sha256`만 쓴다.
- `root/code_map/{code_map_version}/echo_code_map.jsonl` — SUU-104 형식. `{raw_subpart_code: 행}` dict로 만든다. **같은 `raw_subpart_code`가 두 번 나오면** 그 키의 행을 `review_status="conflict"`로 바꾼다 (실제 사전에 깨진 행 7개가 전부 `CAAMACT`).
- 파일 순서 (고정): `echo_zip.ICIS_AIR_MEMBERS` 순서 그대로 10개 → `PIPELINE_CAA_00_COMPLETE.csv`. 이 순서라야 고아·known_activities를 한 번에 계산할 수 있다.

### 필수 열 검사 (jsonl 쓰기 전에)
- 각 파일의 헤더(`csv.reader`로 첫 줄만)에 아래 열이 다 있어야 한다. 없으면 `ParseError(f"{member}: missing required columns: {', '.join(missing)}")`. **`parsed/{as_of}/` 폴더는 검사가 다 끝난 뒤에 만든다.**
  - FACILITIES `PGM_SYS_ID`; PROGRAMS `PGM_SYS_ID, PROGRAM_CODE`; SUBPARTS `PGM_SYS_ID, PROGRAM_CODE, AIR_PROGRAM_SUBPART_CODE`; POLLUTANTS `PGM_SYS_ID, POLLUTANT_CODE`
  - FCES_PCES·STACK_TESTS·TITLEV_CERTS `PGM_SYS_ID, ACTIVITY_ID, ACTUAL_END_DATE`; FORMAL `PGM_SYS_ID, ACTIVITY_ID, SETTLEMENT_ENTERED_DATE, PENALTY_AMOUNT`; INFORMAL `PGM_SYS_ID, ACTIVITY_ID, ACHIEVED_DATE`
  - VIOLATION_HISTORY `PGM_SYS_ID, ACTIVITY_ID`; PIPELINE `SOURCE_ID, EVAL_ACTIVITY_ID, VIOL_ACTIVITY_ID, EA_ACTIVITY_ID, EA_FEA_ACTIVITY_ID` + flag 7열

### 파일 → 함수 → 표
| 파일 | 부르는 것 | 나오는 표 (키) |
|---|---|---|
| FACILITIES | `facility_rows(row)` | `echo_facility (pgm_sys_id)`, `echo_industry (pgm_sys_id, code_system, code)`, `echo_facility_identifier (program_system, pgm_sys_id, registry_id)` — `registry_id`가 None이 아닐 때만 `{"program_system":"ICIS-AIR","pgm_sys_id","registry_id","mapping_source":"ICIS-AIR_FACILITIES.csv","review_status":"source_stated"}` |
| PROGRAMS | `program_row(row)` | `echo_program (pgm_sys_id, program_code)` |
| PROGRAM_SUBPARTS | `subpart_row(row, code_map)` | `echo_program_subpart (pgm_sys_id, program_code, subpart_code)` |
| POLLUTANTS | `pollutant_row(row, n)` | `echo_pollutant (pgm_sys_id, pollutant_key)` |
| FCES_PCES / STACK_TESTS / TITLEV_CERTS | `activity_rows("inspection"/"stack_test"/"titlev", row)` | `echo_activity (activity_kind, activity_id)`, `echo_activity_facility (activity_kind, activity_id, pgm_sys_id)` |
| FORMAL / INFORMAL | `action_rows("formal"/"informal", row, n)` | 위 둘 + `echo_penalty (penalty_key)` (None이면 안 씀) |
| VIOLATION_HISTORY | `violation_rows(row)` | `echo_violation (violation_id)`, `echo_violation_facility (violation_id, pgm_sys_id)` |
| PIPELINE | `pipeline_row(row, n, known)` | `echo_pipeline_link (link_key)` |

- `known` = 지금까지 본 `echo_activity` 키 전부 + `("violation", violation_id)` 전부. 이미 갖고 있는 키 집합을 합치면 된다.

### 행 하나 처리
1. `echo_source_row`에 무조건 1행: `{"source_file", "source_row_no", "raw_payload": row, "row_hash": sha256("\x1f".join(row.values())), "parse_status": "ok"|"held", "error": None|str, "source_object_sha256": 그 ZIP의 manifest sha256}`. 파일 처리 순서대로 이어 쓴다 (첫 줄은 FACILITIES 1행).
2. 파서 함수를 `try`로 부른다. `KeyError`/`ValueError`가 나면 `held`, `error=f"{type(e).__name__}: {e}"`, 그 행은 어느 표에도 안 쓴다. 그 외 예외는 잡지 않는다.
3. 나온 행마다 표별 **키로 중복 검사**:
   - 처음 보는 키 → 쓰고, `키 → 내용해시` 기억 (내용해시 = `json.dumps(행, sort_keys=True, default=...)`의 sha256; 키만 있는 표는 해시 대신 집합)
   - 같은 키·같은 해시 → 안 쓰고 `duplicates[표] += 1`
   - 같은 키·다른 해시 → 안 쓰고 `conflicts[표] += 1`, `conflict_examples[표]`에 `{"key": [키값들], "source_file", "source_row_no"}` 최대 20개
   - 충돌 대상 표(내용이 있는 것): `echo_facility, echo_program, echo_program_subpart, echo_pollutant, echo_activity, echo_violation`. 나머지(`echo_facility_identifier, echo_industry, echo_activity_facility, echo_violation_facility, echo_pipeline_link`)는 중복만. `echo_penalty`·`echo_source_row`는 행마다 키가 달라 검사 안 함.
   - 부모가 충돌이어도 자식(industry 등)은 그대로 자기 표 규칙으로 처리한다.
4. 고아 검사 (쓸 때 바로): `orphans` 키는 테스트에 있는 10개 고정. `pgm_sys_id`는 `echo_facility` 키 집합, `.program`은 `echo_program` 키, `.activity`는 `echo_activity` 키, `.violation`은 `echo_violation` 키에 없으면 +1. `echo_pipeline_link.resolved`는 `resolved_*`가 있는데 집합에 없을 때 (구조상 항상 0).

### report (반환값 = `report.json`, JSON으로 그대로 저장 가능해야 한다 — tuple 금지)
```
{
  "as_of": "2026-09-17", "code_map_version": "...",
  "files": {파일명: {"read", "ok", "held"}},            # 11개
  "identifiers": {파일명: {열: {"missing", "missing_rate", "duplicate", "duplicate_rate"}}},
  "orphans": {...10개}, "duplicates": {...11개 표}, "conflicts": {...6개 표}, "conflict_examples": {표: [...]},
  "penalties": {"rows": 벌금 행 수, "formal_rows_ok": FORMAL의 ok 행 수},
  "subpart_mapping": {"mapped", "unresolved", "conflict"},
  "pipeline": {"resolved", "unresolved", "none", "synthetic_violation"}
}
```
- `identifiers`: 파일에 있는 열만. 대상 열 `PGM_SYS_ID`, `ACTIVITY_ID`, `SOURCE_ID`. `missing` = 값 `""`, `duplicate` = 그 파일 안에서 앞에 나온 값과 같은 행 수. rate = 수/read, `round(x, 4)`. 원본 값 기준(파서 결과 아님).
- `duplicates`·`conflicts`는 0이어도 모든 대상 표 키를 넣는다 (테스트가 dict 통째 비교).

### 출력
- `root/parsed/{as_of}/{표}.jsonl` 13개 (행이 0개여도 빈 파일 생성) + `report.json`.
- `json.dumps(row, ensure_ascii=False, default=_plain)` 에서 `_plain`: `date` → `isoformat()`, `Decimal` → `str()`. 그래서 `activity_date`는 `"2004-05-04"`, `amount`는 `"0"` 문자열.
- 파일 13개를 처음에 한 번 열어두고(`with ExitStack`) 한 줄씩 쓴다.

### 크기
- 표준 라이브러리만 (`csv, json, hashlib, decimal, datetime, contextlib, pathlib`). 200줄 안팎. 파일별 설정은 리스트/튜플 하나로 (클래스 없음).
- 실제 크기 감: 점검 1.8M행 + 인증 2.6M행 → 키 집합 수백만 개는 메모리에 괜찮다. 행 dict를 리스트로 쌓지만 않으면 된다.
