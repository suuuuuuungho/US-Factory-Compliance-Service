# SUU-206 feat(db): FR Part 63 목록·상세·원문을 받아 해시 폴더에 보관

## 목표
명령 한 줄로 Federal Register의 40 CFR Part 63 문서 목록(1,532행)과 문서마다 상세 JSON·본문 XML·공식 PDF를 내려받아 `raw/` 아래 해시 폴더에 보관한다.

## 건드릴 파일
- 만들 것 (`[2] db/pipeline/2_Federal Register/`):
  - `fr_list.py` — `list_url(end_date)`, `collect_list(root, end_date, *, fetch)`: 목록 페이지를 `next_page_url`로 끝까지 따라가 `raw/lists/{end_date}/documents.jsonl`에 쓰고 `{"count", "pages", "rows"}` 반환
  - `fr_fetch.py` — `Fetched`(body·source_url·final_url·http_status·media_type·byte_size·sha256), `fetch(url) -> Fetched`, `detail_url(document_number, publication_date)`, `check_format(body, kind)` / `FormatMismatch`
  - `fr_raw.py` — `store_raw(root, publication_date, document_number, fetched, *, kind) -> entry`: `raw/{연도}/{발행일}_{문서번호}/{sha256}/{문서번호}.{json|xml|pdf}` + 같은 폴더의 `manifest.json`
  - `fr_collect.py` — `collect(root, end_date, *, fetch=fetch) -> dict`, `main(argv)`: `--root`(기본 `[2] db/2) Federal Register`), `--end`(기본 오늘)
- 고친 것 (Claude): `pyproject.toml` pythonpath에 `[2] db/pipeline/2_Federal Register` 추가
- 테스트·fixture (Claude가 씀, Codex 수정 금지): `[2] db/tests/2_Federal Register/test_fr_{list,fetch,raw,collect}.py`, `fixtures/list_page{1,2,3}.json`, `fixtures/detail_*.json`

## Codex 메모
- 본보기: `[2] db/pipeline/3_ECHO/echo_fetch.py`·`echo_raw.py`·`echo_collect.py`, `[2] db/pipeline/1_eCFR/ecfr_fetch.py`(메모리 fetch + gzip). FR 파일은 크지 않으니(XML 최대 수 MB) eCFR처럼 `body: bytes`로 받는다.
- **API 실측** (2026-09-21):
  - 목록: `https://www.federalregister.gov/api/v1/documents.json?per_page=1000&conditions[cfr][title]=40&conditions[cfr][part]=63&conditions[publication_date][gte]=1994-01-01&conditions[publication_date][lte]={end}&order=oldest` → `count` 1,532, `total_pages`, `next_page_url`(마지막 페이지엔 없음), `results`. **`next_page_url`을 그대로 쓴다.** `search_after_cursor`가 들어있어서 `page=N`만 바꿔 만들면 안 된다. `list_url()`의 쿼리 인코딩은 `urllib.parse.urlencode`로 하면 되고 테스트는 `parse_qs`로 비교한다.
  - 목록 행 필드: `abstract, agencies, document_number, excerpts, html_url, pdf_url, public_inspection_pdf_url, publication_date, title, type`. 그대로 jsonl에 쓴다.
  - 상세: `https://www.federalregister.gov/api/v1/documents/{number}.json?publication_date={date}`. **발행일 없이 부르면 `03-5521`은 2003-08-28 정정문만 온다.** 상세 JSON의 `full_text_xml_url`(federalregister.gov, `text/xml`)과 `pdf_url`(govinfo.gov)을 쓴다. 1994년 문서는 `full_text_xml_url`이 `null`일 수 있다 → `missing`에 `reason: "no url"`.
  - 없는 문서는 404 + HTML 본문. XML 자리에 HTML(로그인·차단 페이지)이 올 수 있다 → `check_format`.
- `check_format(body, kind)`: 앞쪽 공백 제거 후 `json`은 `{`/`[`, `xml`은 `<`로 시작하되 `<!doctype html`/`<html`이면 거부, `pdf`는 `%PDF-`. 거부 시 `FormatMismatch(f"{kind} expected, got html")`처럼 kind가 메시지에 들어가야 한다.
- `store_raw` manifest entry 키: `kind, name, path(root 기준 posix), source_url, final_url, http_status, media_type, sha256, byte_size, fetched_at`. 같은 sha256이 이미 있으면 그 entry를 그대로 돌려주고 파일·entry를 추가하지 않는다. manifest 쓰기는 `.part` → `os.replace`.
- `collect` 흐름:
  1. `collect_list` (실패 → `{"status": "failed", "reason": ...}` 반환, 문서 단계 진입 안 함)
  2. 행마다 `detail → xml → pdf` 순. 각 단계는 manifest에 같은 `kind`+`source_url`이 있으면 fetch 생략(재실행 대비). `HTTPError`/`URLError`/`FormatMismatch`/`OSError`는 `raw/lists/{end}/retry.jsonl`에 `{publication_date, document_number, kind, url, reason}` 한 줄 추가하고 다음으로. reason 형식: `"HTTP 404"`, `FormatMismatch`는 그 메시지. detail이 실패하면 그 문서의 xml·pdf도 시도할 수 없으니 `missing`엔 detail만 남긴다.
  3. 반환: `{"status", "end_date", "pages", "count", "documents", "obtained": {"detail","xml","pdf"}, "missing": [{publication_date, document_number, kind, reason}], "started_at", "finished_at"}`. `obtained`는 이번 실행에서 받은 것 + 이미 있어서 건너뛴 것 모두 센다(재실행 테스트가 5·4·5를 기대함). `retry.jsonl`은 매 실행 새로 쓴다.
  4. 순차 실행(호스트당 동시 1). 요청 사이에 짧은 `time.sleep`을 넣고 싶으면 `collect(..., pause=0.0)` 같은 인자로 해서 테스트가 느려지지 않게 한다.
- 원본은 `.gitignore`의 `/[[]2] db/*/raw/`로 이미 제외된다.
- 실제 1,532건 × 3 요청은 SUU-210에서 돌린다. 이 티켓에서는 네트워크를 쓰지 않는다.
