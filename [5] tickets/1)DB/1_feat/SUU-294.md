## Codex 메모

### 1. `echo_parse.py` — Part 63 필터
- 시그니처: `parse_release(root, as_of, code_map_version, *, part63_only=True)`. 기존 인자·순서는 그대로.
- **사전 통과(pre-pass)**: 본 루프 전에 `ICIS-AIR_PROGRAM_SUBPARTS.csv`를 `iter_rows`로 한 번 훑어 `part63_ids: set[str]`를 만든다. 조건: `subpart_row(row, code_map)`의 `cfr_part == "63" and mapping_status == "mapped"`. 약 5만 개라 메모리 문제 없음. `part63_only=False`면 `part63_ids = None`.
- **본 루프**: 각 행에서 시설 ID를 꺼낸다 — ICIS 파일은 `row["PGM_SYS_ID"]`, `PIPELINE_CAA_00_COMPLETE.csv`는 `row["SOURCE_ID"]`. `part63_ids is not None and 시설ID not in part63_ids`면:
  - `report["files"][member]["read"] += 1`(이미 위에서 셈)과 identifier 통계는 그대로 두고,
  - `report["files"][member]["skipped"] += 1` 하고 `continue`. **`echo_source_row`에도 쓰지 않는다** (지금 6.5GB의 원인). ok/held에도 안 센다.
- report 추가: `files[member] = {"read", "ok", "held", "skipped"}` (전국 모드도 `skipped: 0`), `report["scope"] = {"part63_only": bool, "part63_facilities": len(part63_ids) 또는 None}`.
- `echo_check`는 `report.files[].read`를 manifest `row_count`와 비교한다 → `read`는 반드시 원본 행 수 그대로.
- 테스트 fixture: F1에 `CAAMACT6J`(→ 63/JJJJJJ) 추가, F2는 Part 63 아님, F9는 시설 없는 프로그램. 기대값은 `test_part63_only_*` 참조 (activity_facility 5, penalty `formal:1`만, pipeline F1만).
- `__main__` 추가 (CI가 `python "[2] db/pipeline/3_ECHO/echo_parse.py"`로 부른다): `root = parents[2] / "3) ECHO"`, `as_of = raw/ 아래 최신 폴더` (`echo_ingest._latest_as_of` 재사용 가능), `code_map_version = code_map/ 아래 최신 폴더`(지금 `2026-09-17`, git에 있음). 결과 JSON 출력, 실패면 exit 2. `ecfr_parse.py`의 `__main__`과 같은 모양.

### 4. `echo_retire.py` (새 파일)
```python
from echo_parse import TABLES

def retire_other_releases(release_id: str, *, client, conn) -> list[str]:
    with conn.cursor() as cur:
        for table in reversed(TABLES):                       # 자식 표부터 (FK)
            cur.execute(f"delete from {table} where release_id <> %s", (release_id,))
    conn.commit()
    old = client.table("common_dataset_release").select("release_id").eq("dataset", "echo").eq("status", "published").neq("release_id", release_id).execute().data
    archived = [str(r["release_id"]) for r in old]
    for rid in archived:
        client.table("common_dataset_release").update({"status": "archived"}).eq("release_id", rid).execute()
    conn.autocommit = True                                   # VACUUM 은 트랜잭션 안에서 못 돈다
    try:
        with conn.cursor() as cur:
            for table in TABLES:
                cur.execute(f"vacuum analyze {table}")
    finally:
        conn.autocommit = False
    return archived
```
- 가짜 conn/client가 지원하는 것: `cursor()`(context manager), `execute(sql, params)`, `commit()`, `autocommit` 속성 / `select().eq().neq().execute().data`, `update().eq().execute()`.
- 삭제 SQL에 `release_id <> %s`가 글자 그대로 들어가야 한다. `echo_code_map`은 지우지 않는다.
- 실제 DB: `echo_load`처럼 `set statement_timeout = 0`을 먼저 실행하는 게 안전하다 (첫 실행이 전국 2.9GB를 지운다). 가짜 conn은 `set ...`을 무시하므로 넣어도 된다 — 단 테스트는 `delete`로 시작하는 SQL만 센다.
- `common_dataset_current`는 publish가 이미 현재 release로 바꿔 놓았다. 여기서 손대지 않는다.
