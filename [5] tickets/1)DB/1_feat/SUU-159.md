# SUU-159 feat(db): 질문·답·비용을 rag_answer_log 표에 남긴다

## 목표
`/ask` 한 번 = `rag_answer_log` 한 줄(질문·답·조문·issues·토큰·비용·ms·release_id). insert가 깨져도 답은 그대로 나간다. API 호출 없음, $0.

## 건드릴 파일
- 만듦: `[2] db/migrations/SUU-159_rag_answer_log.sql` — DDL 기록(아래 그대로)
- 만듦: `[3] backend/app/log.py` — `answer_log_row(question, result, release_id) -> dict`, `save_answer_log(client, row) -> None`
- 고침: `[3] backend/app/main.py` — lifespan에서 `STATE["client"] = client`, `/ask`에서 답 만든 뒤 `save_answer_log` 한 줄
- 고침: `[1] docs/3) rag/2_rag 구축 계획.md` [8]절에 `rag_answer_log` 항목 추가(티켓엔 `db 구축 계획/`이라 썼지만 `rag_*` 표는 이 문서 [8]절에 있다)

## Codex 메모

### `SUU-159_rag_answer_log.sql`
```sql
-- SUU-159: 서비스 질문 로그. /ask 한 번에 한 줄. 정책 없이 RLS만 켠다 (SUU-63 패턴).
-- 계획 문서: [1] docs/3) rag/2_rag 구축 계획.md [8]절

create table rag_answer_log (
    id bigint generated always as identity primary key,
    created_at timestamptz not null default now(),
    release_id uuid not null references common_dataset_release(release_id),
    question text not null,
    answer jsonb,
    sections jsonb not null,
    issues jsonb not null,
    prompt_tokens integer not null,
    completion_tokens integer not null,
    cost_usd numeric(10, 6) not null,
    ms integer not null
);

alter table rag_answer_log enable row level security;
```
- 테스트는 공백을 하나로 합치고 소문자로 만든 뒤 `create table rag_answer_log (`와 `[(,] 컬럼이름 ` 패턴을 찾는다. 컬럼 하나에 한 줄, 위 모양 그대로면 통과

### `log.py`
- `answer_log_row`: `{"release_id", "question", "answer": result["answer"], "sections", "issues", "prompt_tokens": result["tokens"]["prompt"], "completion_tokens": result["tokens"]["completion"], "cost_usd", "ms"}`. `id`·`created_at`은 DB 기본값
- `save_answer_log(client, row)`: `client.table("rag_answer_log").insert(row).execute()`를 `try/except Exception`으로 감싸고 실패는 `logging.getLogger(__name__).exception("answer log insert failed")`만. 답보다 로그가 덜 중요하다

### `main.py`
- lifespan: `STATE["client"] = client` 한 줄 추가(`STATE = {"index": None, "client": None}`)
- `/ask`: `result = answer_question(...)` 받은 뒤 `if STATE.get("client"): save_answer_log(STATE["client"], answer_log_row(body.question, result, STATE["index"].release_id))` → `return result`
- `test_log.py`의 `FakeSupabase`는 `table().insert().execute()` 체인만 흉내낸다. 그 밖의 메서드를 쓰면 깨진다
