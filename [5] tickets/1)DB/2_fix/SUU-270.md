# SUU-270 fix(db): ECHO 적재 때 1900년 전·2100년 후 날짜를 빈값으로

## 목표
ECHO를 다시 적재해도 가짜 날짜(1900-01-01 전, 2100-01-01 이후)가 날짜 칸에 들어가지 않고 빈값(`None`)이 되게 한다.

## 건드릴 파일
- 고칠 것: `[2] db/pipeline/3_ECHO/echo_values.py`의 `parse_date` 하나만

## 안 하는 것
- `[2] db/tests/` 아래 수정 금지
- `raw_date` / `raw_dates`에 원문을 남기는 호출부(`echo_activities.py`, `echo_actions.py`, `echo_programs.py`, `echo_violations.py`)는 바꾸지 않는다. 이미 원문을 남긴다
- 2027~2028년 같은 가까운 미래 날짜는 지우지 않는다 (계획 중인 시설의 시작일일 수 있음)
- DB 값 수정 안 함. 2026-09-24에 이미 106개를 빈값으로 바꿨다 (SUU-268)
- ECHO 재적재 실행 안 함

| 기존 ECHO 테스트가 모두 통과 | `python -m pytest` 전체 |

## Codex 메모
- `parse_date`는 지금 `%m-%d-%Y`와 `%m/%d/%Y` 두 형식을 `strptime`으로 읽는다. `strptime`은 `0215`년이나 `8888`년도 날짜로 받아들인다.
- 날짜로 읽은 다음 `date(1900, 1, 1) <= 값 < date(2100, 1, 1)`이 아니면 `None`을 돌려주면 된다. 1900-01-01은 포함하고, 2100-01-01은 뺀다.
- 경계는 2026-09-24에 DB를 정리한 SQL과 똑같다: `< '1900-01-01' or >= '2100-01-01'`
- 경계값 두 개는 모듈 상수로 둔다. 예: `_MIN_DATE`, `_MAX_DATE`. 함수 인자로 받게 만들지 않는다.
- `parse_date`를 쓰는 곳은 네 파일이다: `echo_activities.py`, `echo_actions.py`, `echo_programs.py`, `echo_violations.py`. 모두 자동으로 같이 고쳐진다.
