# SUU-124 feat(db): 적재 후 행 수·고아 FK·벌금을 검사한다

## 목표
적재된 release가 jsonl·report.json·manifest와 같은지 DB에서 세어 보고 `{"ok", "problems", "counts"}`를 돌려준다. 공개(SUU-125) 전 관문.

## 건드릴 파일
- 만들 것: `[2] db/pipeline/3_ECHO/echo_check.py` — `check_release(root, as_of, release_id, *, conn) -> dict`
- 이미 있음 (수정 금지): `[2] db/tests/3_ECHO/test_echo_check.py`

## 안 하는 것
- 고치기·재적재, 공개 전환, DB 쓰기 (SELECT만)
- 값 단위 비교 (행 수·합계·관계만)

## 완료 기준 ↔ 테스트
| 완료 기준 | 테스트 함수 |
|---|---|
| 정상 적재 → `ok=True`, `problems=[]`, `counts`에 13개 표 DB 행 수 + `penalty_sum`. 표 13개 count, 관계 10개 LEFT JOIN을 DB에서 센다 | `test_clean_release_is_ok_with_no_problems_and_reports_counts` |
| 행 누락·벌금 추가·고아·짝 깨짐·report≠manifest → `ok=False`, problems에 표/파일 이름과 양쪽 숫자 | `test_missing_row_extra_penalty_orphan_and_report_mismatch_are_reported` |

## 구현 메모 (Codex 토큰 부족으로 Claude가 구현)
- 모든 SQL은 `where ... release_id = %s`로 좁힌다 (테스트가 params에 release_id가 있는지 본다).
- 검사 5종, problems 문자열:
  1. 표별 `select count(*) from {table} where release_id = %s` ↔ jsonl 줄 수 (`echo_source_row`는 `parse_status == "held"` 줄만) → `"{table}: db {n} != jsonl {m}"`
  2. 관계 10개(`echo_parse.ORPHANS` 순서) — 꼭 `from {child} c left join {parent} p on ... where c.release_id = %s and p.<key> is null` 모양 → `"orphan {child}.{name}: {n}"`. FK 제약 때문에 보통 0이지만 계획 3-4가 "보고"를 요구한다. `echo_pipeline_link.resolved`는 `resolved_eval_*`→echo_activity 기준.
  3. `select sum(amount) from echo_penalty where release_id = %s` ↔ jsonl `amount` Decimal 합 → `"echo_penalty sum: db {a} != jsonl {b}"`. `counts["penalty_sum"]`은 `str(Decimal)`.
  4. `select count(*) from echo_pipeline_link where release_id = %s and ((resolved_eval_kind is null) != (resolved_eval_id is null) or (resolved_ea_kind is null) != (resolved_ea_id is null))` → `"echo_pipeline_link broken pairs: {n}"`
  5. `report.json["files"][member]["read"]` ↔ `manifest[].members[].row_count` (DB 안 봄) → `"{member}: report {n} != manifest {m}"`
- 검사 1·2는 `echo_parse.TABLES`·`ORPHANS`를 import해서 순서를 맞춘다. 표준 라이브러리만, 80줄 안팎.
