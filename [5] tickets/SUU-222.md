# SUU-222 feat(db): 회신 본문에서 블록·CFR 인용·관계·시설 후보를 뽑는다

## 목표
SUU-221이 만든 `parsed/{as_of}/adi_page.jsonl`(+ version·entry·entry_document)을 읽어 같은 폴더에 `adi_block`·`adi_cfr_reference`·`adi_document_relation`·`adi_facility_candidate` jsonl과 `enrich_report.json`을 쓴다. 문서에 나온 규정을 전부 '적용됨'으로 만들지 않고(role은 전부 `mention`), Part 60은 Part 63 노드에 붙이지 않고, 시설은 후보로만 둔다.

- `reference_role` 분류(질문 대상/적용/비적용) — 1차는 전부 `mention`

- 단순 "See also M000002"는 관계가 아니다. `amends`도 안 만든다
- 기존 코드(`adi_parse.py`, `adi_documents.py` 등) 수정, DB 적재, 실데이터 실행(SUU-225)

## Codex 메모

### 틀
- `adi_parse.py`(SUU-221)와 같은 모양: 표마다 `json.dumps(row, ensure_ascii=False, sort_keys=True)` 기준 정렬 후 jsonl, 보고서 `status="succeeded"`, `started_at/finished_at`. 출력은 **기존 `parsed/{as_of}` 폴더에 덧쓴다**(폴더를 지우지 않는다 — SUU-221 파일이 있다).
- `pyproject.toml`이 `[2] db/pipeline/4_ADI+CAA`를 pythonpath에 넣어두었다. flat import(`from adi_blocks import split_blocks`).
- jsonl 키 = `[2] db/migrations/SUU-223_adi_tables.sql` 열 이름(release_id류 제외).

### `adi_blocks.split_blocks(version_id, pages)`
- 입력: 그 버전의 `adi_page` 행들(순서 무관, `page_no`로 정렬). `status == "ok"`인 페이지만 쓴다.
- 원문 = ok 페이지 `text_content`를 `"\n\n"`으로 이은 것(= `adi_document_version.text_content`와 같은 규칙). 블록은 이 원문을 **빈틈없이 자른 조각**이다: `"".join(block.text_content) == 원문`. strip 하지 않는다. 원문이 비면 `[]`.
- 자르는 위치 = 표식 줄의 시작. 줄 앞 공백은 허용(`^\s*`).

| 표식(정규식, 줄 시작) | kind |
|---|---|
| `Q\d*\s*:` | `question` |
| `A\d*\s*:` | `answer` |
| `Letter\s*:` | `body` |
| `Conditions?( of Approval)?\s*:?\s*$` (그 줄이 제목만) | `condition` |
| `(Sincerely|Very truly yours|Respectfully)\b` (대소문자 무시) | `signature` |

- 첫 표식 앞 글자: 원문이 ADI 헤더(`Control Number:` 줄이 있음)로 시작하면 `header`, 아니면 `body`. 표식이 하나도 없으면 `body` 1개.
- 연속 표식은 각각 블록. `Abstract:`·`Author:`·`ATLANTA` 같은 줄은 `A\d*\s*:`에 안 걸린다(A 바로 뒤 숫자/공백/콜론만).
- 열: `version_id`, `block_no`(1부터), `page_no`(블록 **시작 글자**가 속한 페이지; 페이지 사이 `"\n\n"`은 앞 페이지로 친다), `kind`, `text_content`, `source_locator`(`page:{page_no};char:{start}-{end}` — 원문 기준 offset), `review_status="검토 전"`.

### `adi_references`
- `parse_citations(text)`: 두 정규식을 돌리고 `start` 순으로 합친다. 반환 dict 키: `raw_citation, title, part, subpart, section, paragraph, start, end`(원문 offset, end는 exclusive).
  - section형: `(?:(?P<title>\d{1,2})\s*C\.?\s?F\.?\s?R\.?\s*)?(?:§§?\s*)?(?P<section>(?P<part>\d{1,3})\.\d+)(?P<paragraph>(?:\([A-Za-z0-9]{1,4}\))*)`. `40 C.F.R. 63.1207(c)(2)`, `40 CFR § 63.7(h)`, `§63.11607(a)(1)`, `40 CFR 60.5175(b)` 모두 여기. title은 있으면 int(40), 없으면 None. part는 section 앞 숫자. paragraph는 `"(c)(2)"` 문자열, 없으면 None. **`CFR`도 `§`도 없는 bare 숫자는 part가 60~63일 때만** 인용으로 친다(소수점 숫자 오탐 줄이기).
  - part+subpart형: `(?:(?P<title>\d{1,2})\s*C\.?\s?F\.?\s?R\.?\s*)?[Pp]art\s+(?P<part>\d{1,3})\s*,?\s*[Ss]ubpart\s+(?P<subpart>[A-Z]{1,7})\b`. `40 CFR part 63, subpart EEE`, `40 C.F.R. Part 63, Subpart AAAAA`. section·paragraph None. `40 CFR Part 63`만 있고 subpart가 없으면 인용 아님.
- `build_node_index(nodes)`: eCFR `nodes.jsonl` 행(`node_key, node_type, identifier`)에서 `{("section", "63.11607"): node_key, ("subpart", "63", "EEE"): node_key}`. node_key가 `40/63/...`으로 시작하는 것만(= part 63).
- `extract_references(version_id, blocks, index)`: 블록마다 `parse_citations(block.text_content)`. 해결 규칙: `title`이 40 또는 None이고, section이 있으면 `("section", section)`, 없으면 `("subpart", part, subpart)`로 찾는다. 찾으면 `current_node_key`+`review_status="검토 전"`, 못 찾으면 `current_node_key=None`+`"미해결"`. Part 60은 index에 없으니 자동으로 미해결.
- 열: `reference_id`(`uuid5(NAMESPACE_URL, f"adi-reference:{version_id}:{block_no}:{start}")`), `version_id`, `block_no`, `raw_citation`, `title`, `part`, `subpart`, `section`, `paragraph`, `reference_role="mention"`, `evidence_locator`(`block:{block_no};char:{start}-{end}` — **블록 글자 기준** offset), `review_status`, `historical_ecfr_release_id=None`, `historical_node_key=None`, `current_ecfr_release_id=None`, `current_node_key`.
- 같은 인용이 두 번 나오면 행 두 개(위치가 다르다).

### `adi_relations.extract_relations(version_id, document_id, blocks, control_to_document)`
- `control_to_document`: `{control_number: document_id}` — `adi_enrich`가 `adi_source_entry`(control_number) → `adi_entry_document`(version_id) → `adi_document_version`(document_id)로 만든다. 문서(PDF)가 없는 항목은 여기 없다.
- 블록 글자에서 `\b[A-Z]?\d{6,8}\b` 토큰 중 `control_to_document`에 있는 것만 본다. 자기 문서(document_id가 같은 것)는 무시.
- 그 언급이 든 **문장** 안의 문구로 종류를 정한다. 문장 경계 = 줄바꿈 또는 `[.;!?]` 뒤 공백. 단 `No.`/`Nos.`의 점은 경계가 아니다(`ADI Control No. M050031`).

| 문장에 있는 문구(대소문자 무시) | relation_type |
|---|---|
| `withdraw` | `withdraws` |
| `rescind` / `supersed` / `replace` | `supersedes` |
| `also filed as` / `also appears in` / `also filed under` | `same_file` |
| 그 밖(`See also …`) | 관계 없음 |

- 순서: withdraw → supersede → same_file 중 먼저 걸리는 것 하나. `(from, to, type)`이 같으면 첫 번째만.
- 열: `from_document_id`(이 문서), `to_document_id`, `relation_type`, `evidence_version_id`(=version_id), `evidence_locator`(`block:{block_no};char:{start}-{end}`, 언급 토큰 위치), `review_status="검토 전"`.
- 문구는 있는데 상대가 `control_to_document`에 없으면 관계를 안 만들고 개수만 센다(→ 보고서 `relation_mentions_skipped`).

### `adi_facilities`
- `normalize_name`: None/빈 문자열 → `""`. 대문자화 → `&`→` AND ` → 영숫자·공백 외 제거 → 공백 압축 → 끝 단어가 `INC, LLC, CORP, CORPORATION, CO, COMPANY, LTD, LP, L P, L L C`면 떼기(반복). 예: `Essroc Cement Corp.` → `ESSROC CEMENT`, `A & B Co., Inc.` → `A AND B`.
- `states_in_text`: 주소 줄 패턴만. `,\s*([A-Z]{2})\s+\d{5}(?:-\d{4})?` 와 `,\s*(주 이름 전체)\s+\d{5}` (주 이름은 대소문자 무시, 50개 주 + DC 표를 모듈 상수로). 반환은 2글자 코드 집합. `IN this letter`처럼 우편번호가 없으면 안 잡힌다.
- `build_facility_index(echo_rows)`: `echo_facility.jsonl` 행(`pgm_sys_id, name, state`) → `{(normalize_name(name), state): [pgm_sys_id, ...]}` (정렬).
- `extract_facility_candidates(document_id, facility_names, text, index)`: `facility_names` = 그 문서에 이어진 항목들의 `facility_name`(None 가능). 정규화 이름이 비면 건너뜀. `states_in_text(text)`의 각 주 × 각 이름으로 index를 찾고, pgm_sys_id로 중복 제거·정렬. 열: `document_id`, `echo_pgm_sys_id`, `match_evidence`(`name:{정규화 이름};state:{ST}`), `review_status="검토 전"`.

### `adi_enrich`
- `TABLES = ("adi_block", "adi_cfr_reference", "adi_document_relation", "adi_facility_candidate")`
- `enrich_all(root, as_of, *, ecfr_nodes, echo_facilities)`: `root/parsed/{as_of}/`에서 `adi_document_version`·`adi_page`·`adi_source_entry`·`adi_entry_document` jsonl을 읽는다. 버전마다 페이지를 모아 `split_blocks` → `extract_references` → `extract_relations` → 시설 후보(text = 원문, facility_names = entry_document로 이어진 항목들의 `facility_name`). `text_content`가 None/빈 버전은 블록 0(보고서 `versions_without_text`).
- 보고서 `enrich_report.json`: `as_of`, `status`, `versions`, `versions_without_text`, `rows`({표: 행 수}), `references_unresolved`(current_node_key None 개수), `relation_mentions_skipped`, `started_at`, `finished_at`. 반환값과 파일이 같아야 한다.
- `main(argv)`: `--root`(기본 `[2] db/4) ADI+CAA`), `--as-of`(기본 `root/parsed/` 아래 이름순 마지막 폴더), `--ecfr-nodes`(기본 `[2] db/1) eCFR/parsed/<최신>/v1/nodes.jsonl`), `--echo-facilities`(기본 `[2] db/3) ECHO/parsed/<최신>/echo_facility.jsonl`). 보고서를 한 줄 JSON으로 print, return 0.
