# SUU-110 feat(db): Pipeline CSV를 pipeline_link 행으로 바꾼다

## 목표
`PIPELINE_CAA_00_COMPLETE.csv` 한 행(dict)을 `echo_pipeline_link` 1행으로 바꾼다. 원본 ID는 다 남기되, `resolved_*`는 실제 activity/violation 집합에 있을 때만 채운다.

## 건드릴 파일
- 만들 것: `[2] db/pipeline/3_ECHO/echo_pipeline.py`
- 이미 있음 (수정 금지): `[2] db/tests/3_ECHO/test_echo_pipeline.py`

## 안 하는 것
- `known_activities` 집합 만들기 (SUU-111이 activity·violation jsonl에서 모아 넘긴다)
- `-9999`나 없는 ID로 activity 행 만들기
- `EA_PENALTY_AMT`·`EA_COMP_ACTION_COST`를 penalty 행으로 만들기 (뜻 검증 전 — attributes에 원문만)
- 날짜·금액 파싱 (이 파일은 연결 증거용; 사실값은 ICIS-Air 쪽 테이블이 갖는다)
- jsonl 쓰기, `release_id`, `tests/` 수정

## Codex 메모

테스트가 부르는 것:

```python
def pipeline_row(row: dict[str, str], source_row_no: int, known_activities: set[tuple[str, str]]) -> dict
```

- 실제 헤더 35열 (2026-09-17 ZIP, 67,122행) — 테스트 파일 `HEADER` 그대로.
  - `EVAL_ACTIVITY_ID`: `-9999` 42,479 / 숫자 24,643. **`EVAL_FLAG=Y`인데 `-9999`인 행 6,970개** → flag를 믿지 말고 ID로 판단.
  - `VIOL_ACTIVITY_ID`: 전부 숫자. `EA_ACTIVITY_ID`: 숫자 46,126 / `""` 20,996. `EA_FEA_ACTIVITY_ID`: 숫자 17,593 / `""`.
  - `VIOL_END_DATE`에 `N/A`, `Unresolved`, `Unresolved (Addressed)` 같은 글자가 온다 → attributes에 **원문 그대로** (`N/A`도 글자다. 여기선 `is_missing`을 쓰지 않는다).
- 키 순서 (테스트가 dict 통째 `==`):
  `link_key, pgm_sys_id, eval_activity_id, violation_activity_id, ea_activity_id, ea_fea_activity_id, flags, synthetic_violation, resolution_status, resolved_eval_kind, resolved_eval_id, resolved_violation_id, resolved_ea_kind, resolved_ea_id, source_row_no, attributes`
- 규칙:
  - `link_key = hashlib.sha256("\x1f".join(row.values()).encode("utf-8")).hexdigest()` (row는 CSV 열 순서 dict — `DictReader`/`iter_rows`가 그 순서로 준다)
  - `pgm_sys_id` ← `SOURCE_ID`
  - 원본 ID 4개 ← `EVAL_ACTIVITY_ID, VIOL_ACTIVITY_ID, EA_ACTIVITY_ID, EA_FEA_ACTIVITY_ID`. **`""`만 None**, `-9999`는 문자열 그대로 (`is_missing` 쓰지 말 것 — 그건 `-9999`도 None으로 만든다)
  - `flags` = 7열 `PIPELINE_FLAG, OFFICIAL_FLAG, EVAL_FLAG, VIOL_FLAG, FOUND_VIOLATION, EA_FLAG, FEA_ISSUE_DATE_FLAG` `{열이름: 값}`, `""`→None
  - `synthetic_violation = row["EVAL_ACTIVITY_ID"] == "-9999"`
  - 찾기: "실제 ID" = `""`도 `-9999`도 아닌 것. 
    - eval: kinds `("inspection", "stack_test", "titlev")` 순으로 `(kind, id) in known_activities` 첫 것 → `resolved_eval_kind/id`
    - violation: `("violation", id) in known_activities` → `resolved_violation_id`
    - ea: kinds `("formal", "informal")` → `resolved_ea_kind/id`
    - `EA_FEA_ACTIVITY_ID`는 찾지 않는다 (FE&C 자료 없음, 원본만)
  - `resolution_status`: 실제 ID가 0개 → `"none"`; 전부 찾음 → `"resolved"`; 하나라도 못 찾음 → `"unresolved"`
  - `attributes` = 위에서 쓴 열(`SOURCE_ID`, ID 4열, flag 7열)을 뺀 나머지 23열, **`""`만 None** (`N/A`는 그대로)
- 이 모듈은 `""`→None만 하므로 `echo_values`를 안 써도 된다. 표준 라이브러리만(`hashlib`), 60줄 안팎.
