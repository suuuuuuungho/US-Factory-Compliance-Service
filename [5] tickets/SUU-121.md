# SUU-121 feat(db): ECHO 전용 테이블 14개를 Supabase에 만든다

## 목표
파서 산출 jsonl 13개 + 코드 사전이 들어갈 `echo_*` 표 14개를 Supabase에 만들고 RLS로 외부 노출을 막는다.

## 건드릴 파일
- 만들 것: `[2] db/migrations/SUU-121_echo_tables.sql` — 적용한 DDL 기록
- Claude가 Supabase MCP(`apply_migration`)로 project `husqnrcuoaogdkbpjnep`에 직접 적용함. Codex 작업 아님

## 안 하는 것
- 데이터 적재 (SUU-123), 인덱스 튜닝(실제 조회 열 확정 후), FE&C 표
- RLS 정책 (SUU-63과 같이 정책 없이 RLS만 켠다 — service_role만 접근)

## 완료 기준 ↔ 확인 방법
| 완료 기준 | 확인 방법 |
|---|---|
| echo_ 표 14개가 보인다 | `information_schema.tables` 조회 → 14, RLS 켜진 표 14 |
| `echo_activity_facility`·`echo_penalty`·`echo_pipeline_link`의 복합 FK가 `echo_activity (release_id, activity_kind, activity_id)`를 가리킨다 | `pg_constraint` 조회로 확인 완료 |

## 적용 결과
- 14개 표: echo_source_row, echo_facility, echo_facility_identifier, echo_industry, echo_program, echo_program_subpart, echo_pollutant, echo_activity, echo_activity_facility, echo_violation, echo_violation_facility, echo_penalty, echo_pipeline_link, echo_code_map
- 열 이름 = jsonl 키 (SUU-111/112 실제 산출물 기준). 계획 3-5절에 없던 열도 jsonl에 있으면 넣었다: facility `source_class_desc/operating_status_desc/local_control_region_*`, program `raw_dates`, subpart `subpart_desc`, pollutant `review_status`, violation `programs/pollutants/attributes`(jsonb), pipeline `attributes`, source_row `error`
- `echo_source_row.source_object_id`는 nullable FK — 적재기(SUU-123)가 jsonl의 `source_object_sha256`을 `common_raw_object`에서 찾아 채운다. 보류(held) 행만 넣는 용도
- `echo_pipeline_link`: `resolved_eval_*`·`resolved_ea_*`는 (kind, id) 둘 다 NULL이거나 둘 다 있어야 한다(check). NULL이면 FK 검사 안 함(MATCH SIMPLE)
- `echo_activity.activity_kind` check: inspection/stack_test/titlev/formal/informal
- `echo_code_map` PK `(dictionary_version, program_code, raw_subpart_code, raw_description)` — 실제 사전 306행에서 중복 0 확인

## Codex 메모
이 티켓은 Codex 작업이 아니다. SUU-122~126의 Python 코드는 이 14개 표가 이미 있다는 전제로 짠다. 열 목록은 `SUU-121_echo_tables.sql`이 원본이다.
