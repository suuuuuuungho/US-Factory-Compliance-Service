이 서비스는 즉시 근거 조문과 함께 답합니다.

## 문제정의

**배경 한 문장:** 미국 공장은 대기 배출 허가(Title V)를 받은 뒤 5년 내내 "우리 공장에 어떤 규정이 적용되는지"를 서류로 반복 증명해야 하고, 그 근거 규정집이 40 CFR Part 63입니다.

공장 환경 담당자 한 사람의 책상 위에 놓인 상황입니다.

**1. 서류는 끝없이 돌아옵니다.** 
   6개월마다 반기 보고, 1년마다 준수 인증, 5년마다 허가 갱신, 초과 배출 시 24시간 내 신고. 
   법이 강제하는 주기입니다. [근거] 40 CFR 70.6(a)(3)(iii), 70.6(c)(5), 70.5(a)(1)(iii)

**2. 서류마다 "어떤 조항 때문인지"를 조항 번호로 반드시 적어야 합니다.**
   위반 보고서에는 어긴 조항 번호를, 준수 인증서에는 어느 조항의 어느 방법으로 확인했는지를 적는 칸이 있습니다.
   빈칸으로 낼 수 없고, "대충 비슷한 조항"을 적으면 틀린 서류가 됩니다.
   [근거] 텍사스 TCEQ, Title V Deviation Reporting and Permit Compliance Certification Guidance

**3. 근거 규정집은 읽을 수 없는 크기입니다.**
   957쪽, 조문 2,473개, 표 784개, 약 463만 토큰. 
   사람이 다 읽을 수 없고, LLM 컨텍스트에도 통째로 안 들어갑니다.

**4. 다 읽어도 소용없습니다. 계속 바뀝니다.**
   2018~2025년 개정 136건, 월 1회 이상. 지금 조문의 45%(1,126개)가 그 사이 바뀌었습니다.
   학습 시점에 멈춘 LLM은 옛 조문을 답하거나 없는 조문을 지어냅니다.

**5. 물어보면 느리고, 사람을 쓰면 비쌉니다.**
   EPA에 공식 판정을 요청하면 회신까지 중앙값 101일. 4건 중 1건(28%)은 6개월 넘게 걸립니다.
   반기 보고 주기가 6개월인데, 답이 그보다 늦게 옵니다. 그래서 문의가 1,127건 쌓여 있습니다.
   변호사·컨설턴트는 매번 쓰기엔 비쌉니다.

**6. 틀리면 내 이름으로 책임집니다.**
   대상 시설 49,618곳 중 27.9%가 위반 이력. 2015년 이후 처분 9,998건, 합계 $958.8M.
   연간 인증서에 "충분히 알아봤고 사실이다"라고 서명하는 사람은 담당자 개인입니다. 틀리면 개인 법적 책임입니다.
   갱신을 놓치면 허가와 함께 공장을 돌릴 권리가 끝납니다.

> 정리하면: 매번 써야 하고, 조항 번호를 꼭 적어야 하는데, 다 읽을 수 없고, 읽어도 바뀌고, 물어봐도 늦고, 틀리면 내가 책임집니다.

## Appeal Point

 ① 기술을 그냥 채택하지 않았습니다. 실험을 통과해야 채택했습니다.

실험 9번 — 채택 6, 기각 3. 임베더 2종, 리랭커 3종, LLM 2종, 하이브리드 가중치 132조합까지,

"좋다더라"로 고른 것이 하나도 없습니다. 전부 같은 평가셋 102건 위에서 전/후 숫자로 결정했습니다.

특히 **점수가 올라도 기각한 실험이 있습니다.** 

정답 조문을 고정으로 끼워 넣는 방식은 지표가 올랐지만(+0.046), 평가셋의 정답을 미리 아는 꼼수라서 버렸습니다.


 ② "판정하지 않는다"를 문구가 아니라 코드 구조로 지켰습니다.

AI가 "적용됩니다"라고 판정하면 사람은 원문을 안 읽습니다. "참고용입니다" 문구로는 행동이 안 바뀝니다.

그래서 답변 JSON에서 `applies` 같은 판정 필드를 아예 삭제해, 시스템이 판정을 구조적으로 말할 수 없게 했습니다.

대신 후보 조항 + 적용을 가르는 기준 + 확인 체크리스트를 주고, 모든 문장에 조문 근거를 답니다.


 ③ 모든 결정을 문서와 티켓으로 남겨, 누가 와도 이어받을 수 있게 했습니다.

기능 하나도 Linear 티켓 없이 시작하지 않았습니다. Linear 티켓 286개(완료 258), 설계 파일 239개.

티켓마다 왜 하는지·무엇을 바꾸는지·완료 기준이 무엇인지를 설계 파일에 적고, 

티켓 번호·브랜치·PR 제목·설계 파일 첫 줄이 서로 같도록 CI가 검사합니다. 설계 파일 없는 PR은 병합이 막힙니다.

그래서 "이 코드가 왜 이렇게 됐지?"에 대한 답이 항상 티켓 하나로 이어집니다. 혼자 만들었지만 혼자만 아는 프로젝트가 아닙니다.


 ④ 테스트를 먼저 쓰게 해서, AI가 만든 코드를 믿을 수 있게 했습니다.

AI가 만든 코드는 "다 됐어요"라는 말을 믿을 수 없습니다. 그래서 "완성"의 기준을 코드보다 먼저 테스트로 못 박았습니다.

Claude가 실패하는 테스트를 쓰고, Codex는 통과만 시킵니다. Codex는 테스트를 고칠 수 없습니다.

PR 254개마다 기존 테스트 772개가 전부 다시 돌아, 옛 기능이 깨지면 병합 전에 잡힙니다.

검색·답변 품질도 같은 방식입니다. 실제 EPA 사례 102건 점수가 합격선 아래면 CI가 병합을 막습니다.

## 결과 — 감이 아니라 실측으로

평가셋은 지어내지 않았습니다. 실제 공장이 EPA에 물은 질문 102건(공식 판정서한)에서 질문과 정답 조문을 뽑았습니다.

| 지표 | 시작 | 최종 | 변화 |
|---|---|---|---|
| 정답 조문이 상위 5개 안에 (Hit@5) | 69% | **93%** | +24%p |
| 검색 순서 품질 (nDCG@10) | 0.437 | **0.692** | +58% |
| 인용 근거율 (지어낸 인용 비율의 반대) | - | **99.6%** | 코드가 자동 제거 |
| 답변 충실도 (RAGAS faithfulness) | - | **0.95** | 심판 LLM 채점 |

**어떻게 올렸나 — 단계마다 실험, 숫자로 채택/기각**

| 단계 | nDCG@10 변화 | 판단 |
|---|---|---|
| 임베더: 일반(bge-m3) vs 법률 특화(Kanon 2) | 0.297 → 0.437 (+0.140) | 채택 |
| 리랭커 3종 비교 | +0.124 | Kanon 2 채택 |
| 하이브리드 검색 (BM25 + RRF) | +0.007, Recall@20 +0.03 | 채택 |
| 후처리 규칙 | +0.063 | 채택 |
| LLM 리랭크 (gpt-5-mini) | +0.061, Hit@5 88→93% | 채택 (응답 +20초 감수) |

**어떻게 지키나**

- 합격선(nDCG@10 ≥ 0.66, Hit@20 ≥ 0.95, 인용 근거율 ≥ 0.96 등)을 CI에 넣었습니다. 
- 점수가 선 아래면 GitHub 병합이 자동으로 막힙니다.

## 혼자 했지만, 팀처럼 일했습니다

저는 방향을 정하고, 판단하고, 검토만 했습니다. 
```
사람 (아이디어·승인) 
→ Claude Code (설계 + 실패하는 테스트 작성)
→ Codex (구현 + PR) 
→ CI (테스트·규칙·품질 합격선 검사)
→ 사람 (직접 병합) 
→ CD (Render·Vercel) 
→ Slack 알림
```

| 17일 | PR 254개 | PR마다 4겹 검사: 테스트·데이터 계약·이름 규칙·품질 합격선 | 사람: 설계 승인·검토·병합 |
|---|---|---|---|

**TDD로 얻은 것 — "테스트 먼저"가 1인 개발을 가능하게 했습니다**

1. **"완성"을 코드보다 먼저 정합니다.** 
   Claude가 실패하는 테스트를 먼저 씁니다. 그게 완료 기준입니다. 
   AI가 "다 했어요"라고 말하는 게 아니라, 테스트가 초록불로 말합니다.

2. **테스트 작성자와 구현자를 분리했습니다.** 
   Codex는 테스트를 고치거나 지울 수 없습니다(작업 규칙으로 금지). 
   구현자가 자기 코드에 맞춰 시험지를 고치는 일을 구조로 막았습니다.

3. **옛 기능이 깨지면 병합 전에 압니다.** 
   PR 254개마다 테스트 772개가 전부 다시 돕니다. 
   혼자 254번 손으로 확인했다면 불가능한 일입니다.

4. **사람은 코드 대신 약속을 검토합니다.** 
   저는 "이 테스트가 무엇을 보장하는가"만 보고 병합합니다. 
   그래서 혼자서 17일에 PR 254개를 처리할 수 있었습니다.

5. **RAG 품질도 같은 방식으로 지킵니다.** 
   검색·답변 합격선을 테스트로 만들어, 점수가 떨어지면 CI가 병합을 막습니다.

병합은 자동화하지 않고 **사람만** 합니다. 중요한 판단에는 사람이 개입합니다.
