# RAG 검색 품질 개선 과정

질문(공장 상황 설명)을 넣으면 40 CFR Part 63에서 **맞는 조문**을 위에 올려주는 검색을 만들고, 점수를 재면서 한 단계씩 고친 기록이다. 2026-09-16 ~ 09-18. 세부 수치는 `[6] rag/eval/results/rag_eval_result.md`, 계획은 `[6] rag/eval/rag_eval_plan.md`.

## 1. 어떻게 점수를 재나

- **평가셋**: EPA가 실제 공장 질문에 답한 회신(ADI·CAA Dashboard)에서 질문 + 정답 조문을 뽑았다. v1 32건(SUU-46) → **v2 102건**(SUU-120). 정답은 케이스당 평균 2.4개 조문.
- **채점표**(SUU-117): 검색 결과 상위 20개 조문을 보고
  - **nDCG@10** (주 지표): 정답이 10등 안에 얼마나 위에 있나. 1이 만점
  - Hit@5 / Hit@20: 정답이 하나라도 5등 / 20등 안에 있는 케이스 비율
  - Recall@20: 정답 조문 중 20등 안에 든 비율
- 0.03 미만 차이는 동점으로 본다(102건에서 3건 차이).

## 2. 검색 조합 이름

| 이름 | 무엇 |
|---|---|
| **baseline** | 조문 청크를 그대로 로컬 bge-m3로 임베딩 → 코사인 상위 (컨텍스트 없음, $0) |

## 5. 배운 것

1. **리랭커가 제일 큰 한 방**(+0.12). BM25 섞기는 작다(+0.007). 가중치 튜닝은 효과 없다.
2. **무료 리랭커로 Kanon을 못 바꾼다**(−0.05~−0.08). 법률 특화 모델 값을 한다.
3. **정답은 이미 후보 안에 있는데 순서가 문제**인 경우가 많다 → 모델 말고 $0 규칙(표 뒤로, Subpart 우선)으로 +0.065.
4. **Subpart A(공통 규정 63.8 등)가 정답인 케이스가 어렵다**. 질문이 특정 공정 얘기라 후보에 안 들어온다. 남은 실패 4건 중 3건.
5. 평가셋을 늘리면 점수는 내려가지만(0.573 → 0.437) 순위는 안 바뀐다. 32건으로 내린 결론이 102건에서도 유지됐다.
6. **임베더가 컨텍스트보다 중요하다**. baseline 0.264에서 컨텍스트는 +0.03, Kanon 2 임베더는 +0.14. 지금 최고(0.631)는 baseline의 2.4배.
7. **LLM 리랭크는 추론 모델이어야 먹힌다**. gpt-4o-mini는 +0.014(순서만 흔듦), gpt-5-mini는 +0.061. 20개 안에서만 바꾸니 Hit@20·Recall@20은 그대로. 질문당 $0.006이지만 ≈ 20초 느림.
