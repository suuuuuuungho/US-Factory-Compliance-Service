# RAG 답변 품질 개선 과정

검색이 골라준 상위 조문을 LLM에 주고 **판정 기준표**(후보 Subpart, 적용 여부를 가르는 기준 + 근거 조문, 공장이 확인할 것)를 만들게 하고, 점수를 재면서 한 단계씩 고친 기록이다. 2026-09-19 ~. 검색 쪽은 `3_rag 검색 품질 개선 과정.md`, 계획은 `[6] rag/eval/rag_eval_plan.md` [14] A-행.

서비스 약속(`1_project.md`): **최종 판정은 주지 않는다.** "어디를 봐야 하고 무엇을 확인해야 하는지"를 준다. 답 모양도 채점표도 이 약속을 따른다.

## 1. 답 모양

입력 = 질문 + 검색 상위 조문 전문(기본 5개). 출력 = 아래 JSON 하나. 필드는 전부 필수.

| 필드 | 뜻 | 규칙 |
|---|---|---|
| `candidates[]` | 후보 Subpart | 1~3개. 넘겨준 조문에 나온 Subpart만 |
| `candidates[].subpart` | Subpart 코드 | 예 `PPPP` |
| `candidates[].title` | Subpart 이름 | |
| `candidates[].criteria[]` | 적용 여부를 가르는 기준 | 1개 이상. 한 문장, "~이면 적용 / ~이면 아님" 꼴 |
| `candidates[].criteria[].criterion` | 기준 문장 | |
| `candidates[].criteria[].citations[]` | 근거 조문 | 1개 이상. **넘겨준 조문 안에서만.** `40 CFR 63.xxxx(a)` 형식 |
| `checklist[]` | 공장이 확인할 것 | 1개 이상 |

없어야 하는 것: `applies`, `verdict`, `conclusion` 같은 최종 판정 필드. 기준을 주되 판정은 공장이 한다.

예시(평가셋 `dashboard-king-systems-2020-06-16`, 메틸렌클로라이드로 플라스틱을 녹여 붙이는 공정):

```json
{
  "candidates": [
    {
      "subpart": "PPPP",
      "title": "NESHAP for Surface Coating of Plastic Parts and Products",
      "criteria": [
        {
          "criterion": "플라스틱 부품 표면 코팅을 하는 HAP 주요 배출원(major source)이면 PPPP 대상이다.",
          "citations": ["40 CFR 63.4481(a)"]
        },
        {
          "criterion": "두 면을 붙이려고 바르는 물질은 '접착제'이고 접착제는 코팅에 든다. 용제만 발라 녹여 붙여도 코팅으로 볼 수 있다.",
          "citations": ["40 CFR 63.4581"]
        },
        {
          "criterion": "배출 한도는 코팅 고형분 1lb당 HAP lb로 정한다. 고형분이 전혀 없으면 한도를 계산할 수 없어 적용이 어렵다.",
          "citations": ["40 CFR 63.4490"]
        }
      ]
    }
  ],
  "checklist": [
    "바르는 물질에 고형분(수지·안료 등)이 조금이라도 들어 있는가",
    "접합 뒤 마른 막(dry film)이 남는가",
    "공장이 HAP 주요 배출원(major source)인가",
    "같은 라인에서 다른 코팅 작업도 하는가"
  ]
}
```

## 2. 채점표

평가셋 v2 102건(`rag_eval_case_v2.jsonl`). 각 케이스에 `gold_subparts`, `gold_citations`, EPA가 실제로 왜 그렇게 판단했는지 적힌 `notes`가 있다.

| 지표 | 무엇 | 계산 | 비용/102건 |
|---|---|---|---|
| Subpart 적중 | 답의 `candidates[].subpart`에 `gold_subparts[0]`이 있나 | 0/1, 케이스 평균 | $0 |
| 인용 Recall | `gold_citations`(조문 단위) 중 답의 `citations`에 나온 비율 | 케이스 평균 | $0 |
| 인용 근거율 | 답의 `citations`가 넘겨준 조문 안에 있는 비율. 밖이면 "지어냄" | 케이스 평균 | $0 |
| **판정 기준 점수**(주 지표) | gpt-5-mini 심판이 답의 `criteria`를 EPA `notes`와 비교 | 0·1·2점(0 틀림 / 1 부분 / 2 맞음), 케이스 평균 → 0~2 | ~$0.3 |

- 조문 단위 비교는 검색과 같다(`rag_eval_plan.md` [3]-1): `40 CFR 63.4481(a)(1)` → `section-63.4481`. 문단 번호는 뗀다.
- 심판 프롬프트에 들어가는 것: 질문, 답 JSON, `notes`. 심판은 "`notes`의 판단 근거가 `criteria`에 담겼는가"만 본다. 최종 결론 일치는 안 본다(답에 결론이 없으므로).
- 심판을 믿어도 되는지는 사람이 10건 읽어 확인한다(A-3, SUU-148). 일치율 70% 미만이면 심판 프롬프트를 고친다.
- 판정 기준 점수와 인용 근거율 중 근거율이 먼저다. 근거 없는 답은 점수가 높아도 못 쓴다.

## 3. 동점 폭

| 지표 | 동점 폭 | 왜 |
|---|---|---|
| 판정 기준 점수(0~2) | 0.06 미만 | 102건 중 3건이 한 단계(1점) 바뀌면 3/102 ≈ 0.03, 두 단계면 0.06. 검색의 "3건 = 0.03"과 같은 논리 |
| $0 지표 3개(0~1) | 0.03 미만 | 3건 차이 |

동점이면 싼 쪽·빠른 쪽을 고른다.
